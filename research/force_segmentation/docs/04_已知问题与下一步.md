# 04 已知问题与下一步

## 1. 尚未解决的问题（按严重度）

### P1 生产推断时只能用 v3 候选边界 → 上限被锁死
训练/评估用了「教师强制」（把标注边界放进候选集）。对**未标注的新日期**，候选集只能来自 v3
超切结果，模型 ≈ v3 水平 + 跨午休能力，达不到 0.844。

可选解法：
- (a) 继续人工标注，让更多「v3 切不出的边界」进入训练，模型学到何时该引入新边界；
- (b) 给候选集加一层**学习式的边界打分**（先生成密集候选，再用权重外的第二个模型筛）——工作量较大；
- (c) 接受 v3 提供边界 + 训练权重决定保留哪些（即"只学合并，不学新边界"），明确告知这是能力边界。

### P2 低效链式合并仍然矛盾
10-28 要求 `13:31-15:47` 把三段低效连起来；10-26 又要求 `15:01-15:51` 不能与相邻低效连。
两者形态相似、标签相反 → 模型目前两边都取不到（10-26/10-27 是主要失分点）。
需要用户提供判据，或引入上下文特征（如"该段是否夹在两个同向大段之间"）。

### P3 长窗口该拆未拆
HK.09988 10-29 的 90m、HK.00883 10-29 的 106m 窗口，用户尚未表态。
这类窗口在图上明显包含多段结构，是下一批标注的重点。

### P4 前缀稳定性（已实测，尚未达标）

指标定义（**生产真正关心的**）：相邻两次计算之间，**两次都已收口**的段边界变化处数
（新收口的段不算漂移；与收盘定稿的差异留到盘后 17:05 定稿解决）。

实测（`seg/stability.py`，5 个样本 × 5 个 checkpoint = 25 步）：

| 配置 | 逐步漂移 | 说明 |
|---|---|---|
| v3 规则堆 | 25 | 对照 |
| dp（离线，每段全局重算） | 30 | 比规则堆略差 |
| **dp（在线：已收口段冻结）** | **22** | 3/5 样本明显改善，1 个样本反而变差 |

逐样本（v3 → dp离线 → dp在线）：
- HK.00700 10-27：1 → 3 → 4
- HK.00700 10-28：3 → 4 → **2**
- HK.00700 10-29：6 → 8 → **1**
- HK.01810 10-29：7 → 6 → **2**
- HK.09988 10-29：8 → 9 → **13**（变差）

结论：
1. 在线冻结是**必要但不充分**——在窗口数适中的样本上有效（8→1、6→2），
   但在窗口最碎的样本（09988，21 窗）会**累积早期错误**，反而更差；
2. 碎票的根因是早期边界本身不稳定 → 需要对最小段长/粒度做更强约束；
3. 落地形态还必须有：最后一段标 `ongoing` + 盘后 17:05 全局定稿
   （与 `build_force_rounds.py` 现有的盘后收口机制一致）。

### P5 覆盖空洞的历史 bug（已修，留档）
V1 合并阶段曾跨午休合并 → 下游按段分组丢弃 → 10-28 出现 52 分钟空洞。
修法：合并阶段禁止跨不连续缺口 + 防御性切开。任何改动后都要做覆盖检查（空洞 0 / 重叠 0）。

## 2. 下一步（建议顺序）

1. **继续标注**（当前瓶颈是标注量，不是算法）
   - 补 HK.09988 / HK.00883 的长窗口判断；
   - 扩到更多股票（近 14 天有 tick 的港股 15+ 只可用；A 股近期无 tick 数据，需先补采集）；
   - 目标：留一股 CV 稳定 > 0.85。
2. **前缀稳定性实测 + 在线化改造**（P4）——这是能否上线的硬门槛。
3. **94 天全样本对照**：段数分布、ER、σfit、λ 跨日 CV。
4. **重跑既有结论**：λ 中位、四象限胜率、买入闸门回测（窗口一变全部失效）。
5. **切换生产**：以开关形式上线，先灰度，确认前端 `grid4/grid5` 密度与明细抽屉条目数。
