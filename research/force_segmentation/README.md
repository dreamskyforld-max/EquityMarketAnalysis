# 分时趋势切分研究（force_rounds 窗口口径）

> **状态：研究性探索，未替换生产算法。**
> 生产窗口口径仍是 `trend_segmenter.layer1_segments` → `force_dynamics.rounds_by_trend`（ZigZag + L1.5 单刀加速）。
> 本目录只做方法研究、人工标注与权重训练，**不改动 `trend_segmenter.py` / `force_dynamics.py` / `build_force_rounds.py`**。

## 1. 为什么有这个研究

生产口径把一天切成「上涨 / 下跌 / 横盘」趋势段，作为多空博弈回合（`force_round_daily`）的窗口。实测暴露的问题：

- **2026-10-29 HK.00700**：`11:04–15:28` 一个 205 分钟的下跌段，里面塞了「推 → 停顿 → 再推 → 停顿」四个不同阶段；用户问的 13:17–13:31 独立下杀完全淹没在里面。
- 根因不是阈值，而是**切分方式**：ZigZag 只在「方向折返 ≥ 0.30%」处切，不认「推动停止」与「速率变化」。

## 2. 研究结论（截至 2026-10-30）

| 结论 | 证据 |
|---|---|
| 现行口径切得太粗，段内结构被抹平 | σfit/σnoise 1.83~2.52（新口径 1.19~1.49）；ER 中位 0.21~0.32（新口径 0.27~0.55） |
| 换成「分段线性 + 全局最优」明显更好 | 同一段内几乎是一条直线，边界落在拐点 |
| **手写合并规则不是可训练结构** | 规则堆在标注集上只到 F1 0.800，且「低效链式合并」在不同日期的标注上互相矛盾（并 A 天就破 B 天） |
| **「V 型反转要保留」不需要特殊规则** | 把尖锐 V 并成一段会让线性拟合残差爆炸，SSE 项天然阻止合并（10-27 ⑦⑧ 实测） |
| 带权代价 + DP 全局最优 > 规则堆 | 全体 F1 **0.844** vs 0.791（19 个样本 / 5 只股票） |
| **跨股票泛化成立** | 留一股票 CV：**0.820**（vs 全局 0.845，只掉 0.025） |
| 午休不算边界（用户确认） | 4 只票午休跳变仅 0.66~1.77σ，连续走势应跨午休成窗 |

训练出的权重（全局，19 样本）：
`[SSE 1.0｜每段 7.32｜方向翻转 29.38｜过短 19.85｜幅度不足 35.74｜低效 5.03]`
→ **幅度不足与方向翻转主导，低效几乎不参与切分**；粒度不是靠限段数，而是靠「有没有分量」。

## 4. 怎么跑（均在**项目根目录**执行）

```bash
# 训练 + 对照（约 3 分钟）
python3 -m research.force_segmentation.seg.train

# 训练 + 留一股票交叉验证（约 10 分钟）
python3 -m research.force_segmentation.seg.train --loo

# 出单日切分图
python3 -m research.force_segmentation.seg.viz HK.00700 2026-10-29

# 盘中前缀稳定性实测
python3 -m research.force_segmentation.seg.stability

# 批量生成待标注包（图 + 窗口清单 + 反馈模板）
python3 -m research.force_segmentation.seg.labelpack HK.09988 2026-10-29
python3 -m research.force_segmentation.seg.labelpack --auto 4 2    # 自动挑 4 票 × 2 天
```

## 5. 标注协议

反馈格式（三种操作），一行一个日期：

```
2026-10-28: ①②合并；⑤在13:20拆开；⑦起点改到14:05
```

- **合并**：`①②合并`
- **拆分**：`⑤在13:20拆开`（会锚到最近极值）
- **移动边界**：`⑦起点改到14:05`

标注约定：**午休不算边界**（连续走势可跨午休成窗）。
标注集见 `seg/labels.py`（唯一真相源），当前 5 只股票 × 19 个交易日 = **237 个窗口**。

## 6. 与生产的关系（切换前必须完成的事）

切换窗口口径会改变 `force_round_daily` 的全部回合，因此**不能悄悄换**：

1. 94 天全样本对照（段数分布、ER、σfit、λ 跨日 CV）；
2. 重跑所有既有结论（λ 中位、四象限胜率、买入闸门回测）；
3. 前缀稳定性实测（盘中每分钟重算，已收口段不得重排）；
4. 前端 `grid4/grid5` 密度与明细抽屉条目数复核。

详见 `docs/04_已知问题与下一步.md`。
