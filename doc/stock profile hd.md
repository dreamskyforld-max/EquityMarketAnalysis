## 0. 执行摘要（TL;DR）

**结论：项目可行，建议立项，采用「分期建设、规则先行、模型渐进」的路线。**

| 评估维度   | 结论                 | 说明                                                         |
| ------ | ------------------ | ---------------------------------------------------------- |
| 需求可行性  | 高                  | 多标签画像比单一打分更适合「多维筛选」场景，目标清晰                                 |
| 数据可行性  | 中高                 | 量价/基本面 2019-now 全量已具备；题材、事件、机构持仓类数据需外补                     |
| 算法可行性  | 中                  | 描述性标签（①-⑨、⑪）完全可行；判断性标签（⑩ 趋势状态、⑫ 预测评分）无 ground truth，须走验证闭环 |
| 工程可行性  | 高                  | 多标签筛选是成熟问题（用户画像/DMP 领域已大规模验证），存储与检索方案明确                    |
| 主要风险   | 标注悖论、前视偏差、合规       | 均有可落地的对冲方案（见第 9 章）                                         |
| 建议首期范围 | 7 个蓝域（①-⑦）+ ⑩ 趋势状态 | 约 8-12 人周，可交付可用的标签库与筛选能力                                   |

**最关键的两个判断：**

1. **架构判断**：「打分排序」与「多标签画像」是两种范式。打分输出单一连续分数，不可组合、不可解释、改一个维度要重训全模型；标签输出离散多维描述，天然支持任意组合筛选、可逐步扩充、可单独验证。用户目标是「按标签多维筛选」，因此**画像范式是唯一正确选择**。
2. **风险判断**：本项目最大的技术风险不是算法，而是**标签没有 ground truth**（尤其 ⑩ 趋势状态类）。业界对此没有银弹，可行路径是「无前视结构定义 + 前瞻收益验证」的迭代闭环，而非端到端监督学习。这一点必须在立项时接受，否则项目会在「标签准不准」上无限打转。

## 1. 项目背景与目标

### 1.1 背景

现有系统围绕「选股打分」构建（12 特征 → 加权评分 → 排序选股），在实践中暴露出三个结构性问题：

| 问题   | 表现                                              |
| ---- | ----------------------------------------------- |
| 不可组合 | 想找「创新药 + 高成长 + 亏损 + 拉升初期 + 南向增持」这类组合条件，打分模型无法表达 |
| 不可解释 | 分数高但说不清「因为什么高」，无法归因，用户不信任                       |
| 难以演进 | 新增一个维度需重训整个模型，且不同维度相互干扰（如 RSI 三周期共线）            |

同时，系统已积累的核心能力（拆单识别、主力意图、资金流向、南向数据、港股全市场行情）如果只服务于一个「总分」，是极大的能力浪费——这些能力天然是**标签**而非**特征**。

### 1.2 核心目标

构建一套**股票画像系统**：为每只股票打上多维度、多层次的标签，形成可组合、可检索、可回溯、可验证的标签体系，支撑：

- 多标签多维筛选（核心场景）
- 组合构建与风格配置
- 风险排查与监控预警
- 分组回测与策略研究
- 个股档案与研究报告自动生成

### 1.3 与「选股打分系统」的本质区别

| 对比项  | 打分排序系统         | 股票画像系统        |
| ---- | -------------- | ------------- |
| 输出   | 单一连续分数（0-100）  | 多维度离散标签集合     |
| 可组合性 | 差（分数不可拆分）      | 强（标签自由交并差）    |
| 可解释性 | 弱（黑箱加权）        | 强（每个标签有明确口径）  |
| 可演进性 | 差（改一处动全身）      | 强（标签独立增删）     |
| 可验证性 | 只能整体验证         | 每个标签单独验证      |
| 特征共线 | 严重（需去共线）       | 基本无（标签各自独立）   |
| 适用场景 | 单一目标优化（如最大化收益） | 多维描述 + 任意组合筛选 |

**重要**：画像系统不取代打分系统，而是**上位**。打分可以退化为画像系统里的一个「预测评分域」标签（第 ⑫ 域），两者是包含关系而非对立。

### 1.4 非功能需求

| 需求       | 目标值                            |
| -------- | ------------------------------ |
| 股票覆盖     | A 股 ~5400 + 港股 ~2600（含港股通）     |
| 标签数量     | 首期约 123 个（见附录 A），成熟期 200-400 个 |
| 更新时效     | 慢标签季/月频；快标签日频（收盘后 2h 内完成）      |
| 查询性能     | 多标签组合筛选 P95 < 2s               |
| **时间回溯** | **必须支持任意历史日期的标签快照（回测基础）**      |
| 可解释      | 每个标签可追溯到计算口径与输入数据              |

## 2. 使用场景定义

标签体系的设计必须由场景驱动。以下是核心用例：

### 2.1 多维筛选（核心场景）

```
示例 1：港股创新药潜伏标的
  市场=港股  AND  行业=生物医药  AND  类型=创新亏损高增长
  AND  趋势状态 ∈ (低位吸筹, 拉升初期)
  AND  南向持股=连续增持  AND  市值档 ∈ (中盘, 小盘)
  AND  NOT 事件风险=解禁临近

示例 2：红利防御配置
  类型=蓝筹大盘  AND  股息率档=高  AND  波动率档=低
  AND  趋势状态=上升趋势确认  AND  NOT 拥挤度=高

示例 3：风险排查
  趋势状态=高位派发  AND  (商誉占比=高 OR 解禁临近 OR 大股东减持)
```

### 2.2 其他场景

| 场景   | 说明                          | 依赖标签域          |
| ---- | --------------------------- | -------------- |
| 组合构建 | 按标签配置敞口（如价值 vs 成长比例）        | ② 规模、③ 估值、⑤ 成长 |
| 监控预警 | 标签变化时触发告警（如「上升趋势确认」→「高位派发」） | ⑩ 趋势状态、⑪ 事件风险  |
| 分组回测 | 按标签分组统计历史表现，验证标签有效性         | 全部 + 快照能力      |
| 个股档案 | 自动生成个股画像卡片                  | 全部             |
| 研究报告 | 按标签聚合生成行业/主题报告              | ⑧ 题材概念、④ 盈利质量  |
| 概念关联 | 产业链上下游、概念联动分析               | ⑧ 题材概念（需图谱）    |

## 3. 业界经验与对标分析

### 3.1 最可借鉴的成熟领域：用户画像 / DMP

股票画像在**方法论**上与互联网用户画像（User Profiling / DMP 人群标签）高度同构，而后者是业界最成熟的标签工程领域。可直接迁移的经验：

| 用户画像实践                 | 迁移到股票画像              |
| ---------------------- | -------------------- |
| 标签分层（一级类目/二级标签/标签值）    | 十二个标签域 → 标签 → 标签取值   |
| 标签元数据（来源、置信度、有效期）      | 同构，必须建立标签元数据表        |
| 多重归属（一个用户可属多个人群）       | 一只股票可属多个概念/风格        |
| 标签衰减（行为标签随时间衰减）        | 趋势状态、题材热度标签需衰减       |
| **标签快照（人群包快照 / 时间旅行）** | **回测必需：能查任意历史日期的标签** |
| RoaringBitmap 做人群交并差   | 同构：多标签组合筛选的性能核心      |
| 规则标签（圈人规则）+ 模型标签（预测分）  | 完全对应：描述性标签 + 判断性标签   |

**关键借鉴**：用户画像领域最重要的工程经验是「**标签必须有快照**」和「**多标签检索用位图**」——这两点直接决定股票画像系统能否用于回测和实时筛选。

### 3.2 金融数据商的标签/分类体系

| 体系     | 代表                                          | 特点              | 对我们的启示                                                  |
| ------ | ------------------------------------------- | --------------- | ------------------------------------------------------- |
| 行业分类   | GICS（11 部门→158 子行业）、申万（31 一级行业）、中信、证监会      | **层级分类、单一归属**   | 标准化行业标签可直接采用，无需自建                                       |
| 概念板块   | 同花顺/东财概念（数百个，动态更新）                          | **多标签、重叠、热点驱动** | 题材域应支持多重归属 + 热度/时效性                                     |
| 风格因子   | Barra CNE6（规模、价值、成长、盈利质量、动量、波动、流动性、杠杆、Beta） | **连续暴露度**       | 采用「连续暴露度 → 分档标签」双轨；但**域划分不强制对齐 Barra 术语**，见 4.2 术语独立性说明 |
| 量化因子库  | 各量化私募因子库                                    | 因子即标签           | 因子可视为「数值型标签」                                            |
| 评级/ESG | 券商评级、ESG 评级                                 | 外部机构标签          | 可作为外部来源标签接入                                             |

**关键借鉴**：

1. **行业分类不要自建**——直接采用申万/中信/GICS 标准，避免维护成本与口径争议。
2. **风格因子用「连续值 + 分档标签」双轨**——这是 Barra 体系的核心设计思想，既保留信息量又支持筛选。
3. **概念板块必须支持多重归属与动态更新**——这是同花顺/东财的标准做法。

### 3.3 内容标签 / 知识图谱实践

- **标签层级与同义词**：概念标签需维护同义词（如「新能源车」=「电动汽车」）与父子关系（如「人工智能」⊃「算力」）。
- **冲突消解**：如同时满足「成长」与「价值」，业界做法是**允许并存**（因为是连续暴露度上的不同位置），而非强制互斥。
- **产业链图谱**：供应链上下游、概念关联适合用图数据库（Neo4j）存储，支持「上游涨价 → 下游受影响」的传导查询。

### 3.4 可借鉴的关键工程实践

| 实践                      | 用途                | 业界成熟度      |
| ----------------------- | ----------------- | ---------- |
| 倒排索引（Elasticsearch）     | 标签 → 股票集合的快速检索    | 成熟         |
| RoaringBitmap           | 多标签交并差（毫秒级）       | 成熟（DMP 标配） |
| Point-in-Time (PIT) 数据库 | 防前视偏差（财报按实际披露日入库） | 量化标配       |
| 标签血缘（Lineage）           | 追溯标签的计算来源与版本      | 成熟（数据治理领域） |
| 特征平台（Feature Store）     | 特征/标签的统一管理与复用     | 成熟         |

### 3.5 业界做法的共性结论（对本项目的直接指导）

1. **标签体系必须分层 + 有元数据治理**——否则标签会失控膨胀成不可维护的泥潭。
2. **规则打底 + 模型增强**，而非纯黑箱——金融场景下可解释性是刚需。
3. **允许多重归属**——真实世界一只股票本就属于多个概念。
4. **标签必须可回溯（PIT）**——否则无法回测，标签系统价值大打折扣。
5. **数值分档优于绝对阈值**——横截面分位（如前 20%）比绝对阈值（如 PE<15）更稳健、跨时期可比。

## 4. 标签体系设计（核心）

### 4.1 设计原则

| 原则  | 说明                                      |
| --- | --------------------------------------- |
| 分层  | 域（12 个）→ 标签（120-400 个）→ 取值（枚举/分档/布尔/连续） |
| 正交  | 同一域内标签尽量正交，避免共线（这是打分系统的老问题）             |
| 可解释 | 每个标签有明确、可追溯的计算口径                        |
| 相对化 | 优先用横截面分位而非绝对阈值（跨时期可比）                   |
| 可回溯 | 所有标签带生效日期与快照                            |
| 可演化 | 标签可独立增删，不影响其他标签                         |


### 4.2 十二个标签域

| 域 | 名称    | 回答的问题      | 判定标准（可操作）                                | 更新频率    | 生成方式            |
| - | ----- | ---------- | ---------------------------------------- | ------- | --------------- |
| ① | 证券属性  | 这是什么证券？    | 由交易所规则 / 监管分类 / 注册信息决定，**与股价、成交量、财务均无关** | 季/事件    | 外部映射 + 规则       |
| ② | 规模属性  | 它有多大？      | 由市值、营收、资产规模派生；**时变量**                    | 月/日     | 统计分位 + 规则       |
| ③ | 估值水平  | 贵还是便宜？     | **股价或市值 ÷ 公司经营基本面**（盈利/资产/销售/现金流）及其倒数    | 日（随价变）  | 统计分位 + 规则       |
| ④ | 盈利质量  | 公司好不好？     | **纯财报三表，不含价格**，且是**水平 / 比率**             | 季（财报驱动） | 规则 + 分位         |
| ⑤ | 成长特征  | 长得快不快？从哪来？ | **纯财报，不含价格**，且是**变化率 / 投入强度**            | 季（财报驱动） | 规则 + 分位         |
| ⑥ | 股东回报  | 给股东返多少？    | 分红与回购相关，属**分配行为**而非经营基本面                 | 季（分红驱动） | 规则 + 分位         |
| ⑦ | 交易特征  | 怎么被交易？     | **纯行情统计派生，不含任何财务数据**；横截面分位               | 月/日     | 统计分位            |
| ⑧ | 题材概念  | 属于什么故事？    | 市场约定的叙事归属，**多重归属**                       | 事件驱动    | 外部映射 + NLP      |
| ⑨ | 资金关注度 | 谁在买卖？      | 资金流向、持仓变化、市场关注度                          | 日       | 规则 + 统计         |
| ⑩ | 趋势状态  | 处在什么阶段？    | 由**量价走势的可观测结构**判定；个股时序分位、**互斥状态机**       | 日       | **规则标注 → 模型蒸馏** |
| ⑪ | 事件风险  | 有什么雷？      | 公告、监管、财务风险事件                             | 实时/日    | 规则 + 事件流        |
| ⑫ | 预测评分  | 模型怎么看？     | 模型输出，**必须带置信度**                          | 日       | 模型（需严格验证）       |

**蓝域（①-⑨、⑪）为描述性标签，可规则化、风险低；橙域（⑩⑫）为判断性标签，无 ground truth、需验证闭环，风险高——这是资源分配的根本依据。**

> **术语独立性说明**：本体系的域划分**不与 Barra 因子体系强制对齐**。Barra CNE6 将 Value / Growth / Quality 也称为「风格因子」，但其输入是财务数据；本体系中这些归入基本面域（③④⑤），**⑦ 交易特征只保留纯量价派生的统计暴露**。理由是：Barra 是**风险模型**（目的是解释收益协方差），画像是**描述体系**（目的是多维刻画与筛选），目的不同不可照搬。若后续需做风险归因，应**单独建立映射表**维护，不污染标签体系。

**③④⑤ 三域的分界（最易混淆，务必按此判定）**：

1. 先问**是否含价格** → 含价格且分母为经营基本面 = ③ 估值水平；
2. 不含价格（纯财报）再问**是水平还是变化率** → 水平 / 比率 = ④ 盈利质量；变化率 / 投入强度 = ⑤ 成长特征；
3. **股息率、分红率例外**：属分配行为而非经营基本面，归 ⑥ 股东回报。


### 4.3 各域标签清单（首期建议）

#### ① 证券属性（12 个）

**定义**：描述证券的**静态登记与归属**，回答「这是什么证券、在哪交易、属于哪个官方分类」。  
**判定标准**：取值由交易所规则、监管分类、公司注册信息决定，**与股价、成交量、财务表现均无关**——这是它与其余所有域的根本分界。

| 标签          | 取值                           | 来源   |
| ----------- | ---------------------------- | ---- |
| 市场          | A股 / 港股                      | 基础   |
| 交易所与板块      | 主板/创业板/科创板/北交所/港股主板/港股创业板    | 基础   |
| 证券类型        | 普通股 / 优先股 / 存托凭证(DR) / B股    | 基础   |
| 地域          | 注册地、办公地（省/市）                 | 基础   |
| 所有制         | 国资 / 民营 / 外资                 | 外部   |
| 上市年限档       | 次新(<1y) / 成熟(1-5y) / 老股(>5y) | 规则   |
| 申万一级行业      | 31 类                         | 外部标准 |
| 申万二级 / 三级行业 | —                            | 外部标准 |
| GICS 行业     | 可选，用于跨市场对比                   | 外部标准 |
| 是否多地上市      | A+H 同时上市                     | 规则   |

> **移出项**：市值档、指数成分、港股通标的 → ② 规模属性（时变量，非静态身份）；ST / 退市 → ⑪ 事件风险（风险状态）。  
> **行业 vs 概念**：行业是**官方标准分类**（单一层级归属、稳定），在本域；概念是**市场约定叙事**（多重归属、动态），在 ⑧ 题材概念。

#### ② 规模属性（8 个）

**定义**：描述公司在**资本市场的体量**，回答「有多大」。  
**判定标准**：由市值、营收、资产规模派生；**时变量**（随股价与财报变化），故与 ① 证券属性（准静态）分离。

| 标签      | 取值                                   | 说明        |
| ------- | ------------------------------------ | --------- |
| 总市值档    | 特大 / 大 / 中 / 小 / 微                   | 横截面分位     |
| 自由流通市值档 | 五档                                   | 剔除限售与控股部分 |
| 营收规模档   | 五档                                   | 行业内分位更可比  |
| 总资产规模档  | 五档                                   | —         |
| 行业规模排名  | 具体排名                                 | 龙头识别      |
| 指数成分    | 沪深300 / 中证500 / 中证1000 / 上证50 / 恒生系列 | 外部        |
| 港股通标的   | 布尔                                   | 外部        |

> **说明**：指数成分与港股通资格，是指数编制规则对「规模 + 流动性」的**官方认定结果**，故归入本域而非 ① 或 ⑦。

**双轨设计**：上述标签同时保留**连续值**（供研究/回测）与**分档标签**（供筛选）。

#### ③ 估值水平（10 个）

**定义**：描述**价格相对于公司经营基本面**的贵贱，回答「贵还是便宜」。  
**判定标准**：计算形如「股价或市值 ÷ 经营基本面指标（盈利 / 资产 / 销售 / 现金流）」及其倒数。**分母必须是经营基本面**——这是它与 ⑥ 股东回报的根本分界。

> **PS/PCF 口径：只算一处（2026-09 起）**
> 行情表**不存** `ps_ttm_ratio` / `pcf_ttm_ratio` 这类派生列。背景：外部源不提供 PS/PCF，
> 曾由「东财直采（A 股）+ 本地推算（港股）+ 采集脚本钩子」三路分别写表，其中港股一路把
> 累计口径的 Q1/H1/Q3/annual 直接求和（`SUM(近4期)`），分母虚高约 **2.4 倍**、
> 取 A 股对照东财 PS 得比值恒为 **0.42**；且该列日常链路填不满，导致 PS/PCF 标签有效行数一度为 0。
> 现收敛为单一实现：
> - 分子 = 行情表 `total_market_val`（外部源直供、日采必写）；
> - 分母 = `profiling.quantile.load_financial_ttm`（滚动 12 个月的营收 / 经营现金流 / 净利，
>   **全仓唯一实现**，PS/PCF/PEG 共用；公式 `TTM = 本期累计 + 上年全年 − 上年同期累计`，
>   校验：对标东财 PS 比值中位 1.000、94.2% 误差 <5%）。
> 标签层只引用该 helper，不再自带公式；回填脚本回归「补外部缺失原值」职责。

| 标签          | 说明              |
| ----------- | --------------- |
| PE(TTM) 档   | 市值 / 净利润        |
| PB 档        | 市值 / 净资产        |
| PS 档        | 市值 / 营业收入       |
| PCF 档       | 市值 / 经营现金流      |
| PEG 档        | PE(TTM) / 净利 TTM 同比增速，行业内排位（历史口径，非一致预期） |
| EV/EBITDA 档 | 含债口径，跨行业可比性更好   |
| FCF 收益率档    | 自由现金流 / 市值      |
| AH 溢价率      | A 股相对 H 股的估值差   |
| 估值历史分位      | 个股自身历史区间的分位（时序） |
| 估值行业分位      | 同行业内的横截面分位      |

> **必须双分位**：不同行业估值中枢差异极大，只给历史分位或只给行业分位都会误导，两者需并存。

#### ④ 盈利质量（12 个）

**定义**：描述**公司本身的经营品质**，回答「这是不是一门好生意」。  
**判定标准**：**全部来自财报三表，不含价格**，且描述的是**水平 / 比率**（非变化率）——这是它与 ③ 估值、⑤ 成长的双重分界。

| 标签           | 说明                         |
| ------------ | -------------------------- |
| ROE 档、ROIC 档 | 盈利能力核心指标                   |
| 毛利率档、净利率档    | 盈利空间                       |
| ROE 稳定性      | 近 3 年 ROE 波动率，**质量的核心是稳定** |
| 盈利真实性        | 经营现金流 / 净利润、应计项目占比（识别纸面利润） |
| 财务稳健性        | 资产负债率、有息负债率、利息保障倍数         |
| 资产效率         | 总资产周转率、应收 / 存货周转           |
| 连续盈利年数       | —                          |
| 营运资本异常       | 存货 / 应收周转显著恶化              |

> **说明**：杠杆与财务健康属本域（属财务特征），不再作为「风格因子」重复出现——这与 MSCI Quality 指数的定义一致（高 ROE + 低杠杆 + 盈利稳定）。

#### ⑤ 成长特征（9 个）

**定义**：描述公司**规模扩张的速度与投入方向**，回答「长得快不快、增长从哪来」。  
**判定标准**：来自财报的**变化率**（增速）与**投入强度**；**不含价格**。

| 标签                | 说明                   |
| ----------------- | -------------------- |
| 营收增速档、净利增速档、扣非增速档 | 三者需并存（扣非可识别非经常性损益粉饰） |
| 成长持续性             | 连续 N 期正增长            |
| 成长加速度             | 增速的二阶变化（加速 / 减速）     |
| 成长来源              | 内生增长 / 并购驱动          |
| 研发费用率档            | 投入强度                 |
| 资本开支强度档           | 扩张意愿与行业属性            |
| 员工规模增速            | —                    |

> **成长与质量是两个独立维度**：高增长低质量（烧钱扩张）与低增长高质量（现金牛）都是常见且有效的组合，**不可混为一谈**。

#### ⑥ 股东回报（6 个）

**定义**：描述公司**向股东返还现金的方式与力度**，回答「股东能拿回多少」。  
**判定标准**：分红与回购相关，属**分配行为**而非经营基本面。

| 标签        | 说明                           |
| --------- | ---------------------------- |
| 股息率档      | 每股股息 / 股价（含价格，但回答「回报」而非「贵贱」） |
| 分红率档（派息率） | 分红 / 净利润，**不含价格**            |
| 连续分红年数    | 分红纪律                         |
| 分红增长性     | 股息的持续增长能力                    |
| 回购力度      | 回购金额 / 市值                    |
| 股东回报率     | （分红 + 回购）/ 市值                |

> **划归依据**：分红率不含价格，按定义不属于 ③ 估值；股息率虽含价格，但回答的是「回报多少」而非「贵不贵」。红利 / 高股息是 A 股与港股的一等筛选维度（红利策略、恒生高股息），故独立成域以便检索。

#### ⑦ 交易特征（9 个）

**定义**：描述股票在**交易行为层面**呈现的统计特征与风险暴露，回答「它怎么被交易、波动特性如何」。  
**判定标准**：由**行情数据（价格、成交量）的统计特征**计算，**不含任何财务数据**；采用**横截面分位**（同日全市场比较）。

| 子组  | 标签                        | 说明         |
| --- | ------------------------- | ---------- |
| 趋势性 | 动量档（12-1 月）、反转档（1 月）      | 方向性统计特征    |
| 波动性 | 年化波动率档、Beta 档、残差波动档、下行波动档 | 波动与系统性风险暴露 |
| 活跃度 | 流动性档（日均成交额 / Amihud）、换手率档 | 好不好买卖、交易热度 |
| 风险  | 最大回撤档                     | 极端下跌风险     |

> **与 ⑩ 趋势状态的分工**：⑦ 是**横截面统计暴露**（不互斥、确定性、无需验证）；⑩ 是**时序状态机**（互斥、判断性、需验证闭环）。⑩ 的判定不读取 ⑦ 的分档结果，两者交叉组合产生增量筛选价值。

#### ⑧ 题材概念（10 个）

- 概念板块标签（同花顺/东财概念体系，多重归属）
- 产业链位置（上游/中游/下游）
- 政策主题（如「专精特新」「国产替代」「出海」）
- 热点关联度（当前市场热点匹配度，日频）
- 题材纯度（主营与概念的匹配程度）

> **注意**：概念标签是**多重归属**的，一只股票可同时挂 5-20 个概念。且概念有热度与时效性，需带「热度分」与「生效/失效时间」。

#### ⑨ 资金关注度（15 个）

- 北向/南向持股占比档、连续增减持天数
- 主力资金净流入档（日/5日/20日）
- 机构持仓变化、基金重仓
- 融资融券余额变化
- 股东户数变化（减少=筹码集中）
- 龙虎榜出现频率、游资/机构席位
- 研报覆盖度、评级变化
- 成交量能异常（放量/缩量）

#### ⑩ 趋势状态（判断性标签，分期建设）

**建设顺序（2026-09 更新）**：本域是唯一需要「无前视定义 + 前瞻收益验证」闭环的橙域，6 阶段状态机短期无法收敛，故**先落共享的位置要素，再落状态机**：

| 顺序 | 标签 | 性质 | 状态 |
| -- | ---- | ---- | ---- |
| 1 | 股价52周位置档 `tst_price_position_52w` | 确定性要素（位置） | ✅ 已实现 |
| 2 | 趋势阶段 `tst_stage` | 判断性状态机（6 阶段） | ⏳ 待建：需 t+20 / t+60 前瞻收益验证闭环 |

先落位置档的理由是双重的：① 让本域立刻可用——已可独立筛选，也可与其他域交叉；② 6 阶段定义里各自重复的「价格分位<30% / >80%」阈值有了统一口径来源，避免将来各写一套。

##### 10.1 股价52周位置档 `tst_price_position_52w`

| 项目 | 说明 |
| ---- | ---- |
| 计算口径 | 位置 = (收盘价 − 窗口最低价) / (窗口最高价 − 窗口最低价) × 100，落在 0-100 |
| 窗口 | 截至 as_of 的近 **252 个交易日**（与 ⑦ 同为交易日口径）；最高/最低取日内 high / low，收盘取当日 close |
| 取值 | 1=[0,20) 贴近 52 周低点；2=[20,40)；3=[40,60)；4=[60,80)；5=[80,100] 贴近 52 周高点 |
| 双轨 | `num_value` 保留连续位置值（0-100），分档不丢精度 |
| 数据来源 | `a_daily_quote` / `hk_daily_quote`（high / low / close） |
| 更新频率 | 日 |
| PIT | 是（仅用 t 及之前的量价，任意历史 as_of 可回溯） |

**三条关键口径决定**：

1. **用个股自身区间的绝对分档，不做市场内五等分**。本域判定标准是「个股跟自己历史比」，做成横截面就退化成 ⑦ 的口径了；且绝对分档的**分布偏斜本身就是市场状态信号**——2026-09 全市场多数落在 1-2 档，2025-09 则多数落在 4-5 档，横截面五等分会强制把这一信息抹平。
2. **窗口自己回算，不读 `high_52w` / `low_52w` 快照列**。该列在 `hk_daily_quote` 覆盖 100%，但在 `a_daily_quote` 仅回填最近十余个交易日（历史覆盖≈0）。直接读会让本标签在今天看起来完全正常，却在绝大部分历史日期静默产出空值、直到回测才暴露。自己按 252 个交易日回算则任意历史 as_of 都成立（实测与供应商快照列位置差中位数 0.09pp，残余差异来自「252 交易日 vs 自然 52 周」口径）。
3. **不做「满 52 周」覆盖率门槛**：上市不足一年的股票（如 `HK.02513` 窗口内仅 165 行）也照常出值，用其窗口内可用历史区间计算位置。本标签定位是「看股价处于自身历史区间的哪一段」，而非严格的 52 周统计；与个股概览页（直接用 `high_52w`/`low_52w` 快照列、不过滤）同口径，过滤太严会让大量次新/近期上市股丢失该标签、与页面显示不一致。

   **仅剔除退化/空值样本**：区间须有真实宽度（`high > low`，单日股 `high==low` 自然排除）、端点为正、收盘为正；无需额外的「新鲜度」门槛，停牌几天仍保留、长期退市者因无有效行自然排除。

   **先剔除坏快照行再算极值**：港股行情存在 `high=0, low=0` 的脏数据（占比约 2.2%、波及半数港股），若直接取 `min(low)` 会让单条 0 毒化整只股票。故先过滤 `high/low/close ≤ 0` 与 `high < low` 的行，再算区间高点/低点。

> **它能替代 6 阶段状态机吗？不能。** 位置档回答「处在自身 52 周区间的哪一段」，是**位置**；阶段回答「处在趋势的哪个阶段」，是**状态**。贴近 52 周高点的标的可能是主升途中，也可能是深跌后刚反弹——位置相同而性质相反，区分它们正是 6 阶段状态机要做的事。正确用法是与其他域交叉：如「位置档 1 + 南向连续增持」= 左侧布局候选；「位置档 5 + 高位派发」= 强弩之末。

##### 10.2 趋势阶段（6 阶段状态机，待建）

| 标签值    | 可观测定义（仅用 t 及之前）                                   |
| ------ | ------------------------------------------------- |
| 低位吸筹   | 价格分位<30%；量能温和放大(1.2~2×)但价平；波动收敛；资金净流入             |
| 拉升初期   | 突破 60 日平台；放量(>1.5×)；MA20 上穿 MA60；相对强度由负转正；分位仍<60% |
| 上升趋势确认 | MA 多头排列；回踩不破 MA20；相对强度持续为正；量能稳定                   |
| 高位派发   | 分位>80%；放量滞涨/长上影；换手率同类型分位极高；资金净流出                  |
| 下跌     | 空头排列；反弹不过前高；相对强度为负                                |
| 震荡     | 区间宽度<阈值；均线缠绕；波动率低；相对强度≈0                          |

> **三条关键约束**：
>
> 1. 该标签**必须同类型 / 同行业内相对化**（题材股换手率天然高）。
> 2. **判定用个股时序分位**（自己跟自己历史比），而非 ⑦ 交易特征的横截面分位——两者虽都叫「波动率 / 动量」，但计算口径完全不同。
> 3. **必须从原始量价直接计算，不读取 ⑦ 的分档标签**——避免信息损失、口径错配与版本耦合。

> **与 ⑦ 交易特征的关系**：不冲突，是两个抽象层。⑦ 是「要素测量」（温度/湿度/风速，横截面统计暴露、不互斥、确定性）；⑩ 是「状态判断」（晴/雨/多云，时序状态机、互斥、需验证）。两者交叉组合产生增量信息——如「高动量 + 拉升初期」= 强势启动，「高动量 + 高位派发」= 强弩之末。

#### ⑪ 事件风险（22 个）

财报披露临近/超预期/低于预期、业绩预告、大股东增减持、解禁临近、股权质押比例高、商誉减值风险、诉讼/监管问询、ST 风险、退市风险、停牌、可转债/再融资、管理层变动、审计意见异常。

#### ⑫ 预测评分（4 个，判断性，需严格验证）

拥挤度档、预期收益档、风险预警档。

> **建议**：首期只做「拥挤度」与「趋势状态置信度」，其余预测性标签待验证体系成熟后再上。

| ⑧ 题材概念  | 概念板块、产业链、新闻         | **缺口较大**             | 需外采（同花顺/东财概念）或自建 NLP |
| ⑨ 资金关注度 | 北向/南向、龙虎榜、融资融券、股东户数 | 南向/港股 ✓；拆单 ✓（近期）     | A 股北向、龙虎榜、股东户数、研报    |
| ⑩ 趋势状态  | 量价 + 资金             | **量价 2019-now 全量 ✓** | 资金类为近期（增强项）          |
| ⑪ 事件风险  | 公告、解禁、减持、监管         | **缺口较大**             | 需公告数据源               |
| ⑫ 预测评分  | 上述全部                | 依赖前序                 | —                    |

### 5.2 关键数据风险与对策

| 风险              | 影响                         | 对策                            |
| --------------- | -------------------------- | ----------------------------- |
| **前视偏差（PIT）**   | 财报按报告期而非**实际披露日**入库 → 回测虚高 | **必须建立 PIT 数据库**：财务数据以实际披露日生效 |
| **幸存者偏差**       | 只含现存股票 → 回测虚高              | 股票池必须**包含已退市股票**及其历史数据        |
| **复权处理**        | 分红送转导致价格跳变                 | 统一后复权价计算技术指标，另存原始价            |
| **行业分类变更**      | 历史行业归属变化                   | 行业标签需带生效时间，按 PIT 取用           |
| **资金/拆单仅近期**    | 无法长历史验证                    | 作为增强标签，明确标注数据起点               |
| **概念/事件数据外采成本** | 预算与合规                      | 首期可先用简化版（自建关键词匹配），后期评估采购      |

### 5.3 数据可得性结论

**核心结论：⑦ 交易特征 与 ⑩ 趋势状态 的数据基础（量价 2019-now 全量）最扎实，应优先建设。** ①②④⑤ 依赖外部标准数据与财报，补齐成本可控；③ 需财报 PIT 支持；⑥⑧⑨⑪ 存在真实缺口，建议首期用简化方案或延后。

## 6. 标签生成方法（算法可行性）

### 6.1 四类生成方式

| 方式            | 适用                         | 优点         | 缺点        |
| ------------- | -------------------------- | ---------- | --------- |
| **规则/阈值**     | 证券属性、事件风险、部分盈利质量           | 可解释、确定、零训练 | 覆盖不全、阈值需调 |
| **统计/分位**     | 规模、估值、盈利质量、成长、股东回报、交易特征、资金 | 跨期可比、自适应   | 需足够横截面样本  |
| **模型（分类/聚类）** | 趋势状态、题材概念、预测评分             | 泛化、能发现新模式  | 需验证、可解释性弱 |
| **外部映射**      | 行业、概念、评级                   | 权威、省事      | 依赖外部、成本   |

### 6.2 各域推荐方法

| 域       | 主方法               | 备选/增强                |
| ------- | ----------------- | -------------------- |
| ① 证券属性  | 外部映射 + 规则         | —                    |
| ② 规模属性  | 横截面分位（保留连续值）      | —                    |
| ③ 估值水平  | 统计分位（双分位：历史 + 行业） | —                    |
| ④ 盈利质量  | 规则 + 分位（注意 PIT）   | 财务造假识别模型（后期）         |
| ⑤ 成长特征  | 规则 + 分位（注意 PIT）   | —                    |
| ⑥ 股东回报  | 规则 + 分位           | —                    |
| ⑦ 交易特征  | 横截面分位（保留连续暴露度）    | 聚类验证分档合理性            |
| ⑧ 题材概念  | 外部概念映射（首选）        | NLP 从公告/新闻抽取（自建）     |
| ⑨ 资金关注度 | 规则 + 统计分位         | 拆单识别模型（已有）           |
| ⑩ 趋势状态  | **规则标注 → 蒸馏监督模型** | **HMM 无监督状态发现作交叉验证** |
| ⑪ 事件风险  | 规则 + 事件流解析        | NLP 公告解析             |
| ⑫ 预测评分  | 监督模型（严格时序 CV）     | 首期限保守范围              |

### 6.3 趋势状态标签的专门方案（核心难点）

趋势状态（吸筹/拉升/派发…）**没有 ground truth**，这是本项目最大的算法挑战，也是「标注悖论」的正面战场。可行路径：

```
① 可观测结构（t 及之前的量价/资金）
        ↓  规则定义（无前视）
② 阶段标签
        ↓  前瞻收益验证（t+20 / t+60）
③ 有效性检验：各阶段前瞻收益是否显著分离且方向符合预期
        ↓  不通过则回改规则
④ 迭代至收敛 → 得到可信标签集
        ↓
⑤ 蒸馏为监督模型（LightGBM），严格时序切分
        ↓
⑥ HMM 无监督状态发现作交叉验证
   （一致 → 规则可信；不一致处 → 潜在新模式）
```

**关键方法论**：阶段标签的**定义不依赖未来**，但**验证使用未来**。这打破了「用未来定义吸筹 → 循环论证」的悖论。这是业界处理无监督状态标注的标准思路（定义与验证分离）。

**训练要点**：

- 样本 =（股票, 日期）；特征只用 t 及之前
- 严格时序切分：train 2019-2022 / val 2023-2024 / test 2025-2026
- 扩样窗口 CV + `GroupKFold(by stock)` 防同股泄露
- 类别不平衡（震荡/下跌占比高）→ `class_weight='balanced'`
- 软标签：边界样本用 HMM 后验概率，或标「过渡」
- **前瞻收益绝不进特征**

**验证要点**：

- 各阶段 t+20/t+60 前瞻收益的均值/中位数/胜率 + t 检验（第一道关）
- 转移矩阵合理性（吸筹→拉升、拉升→派发概率）
- 类型 × 阶段 分层回测
- Regime 稳定性（牛/熊/震荡分段）
- 人工抽检 + 研报素材校准

### 6.4 标签置信度

模型类标签（⑩⑫）必须输出置信度，供筛选时加权或过滤：

- 规则类标签：置信度 = 1.0（确定性）
- 统计分位类：置信度 = 1.0（确定性，但可标注样本量）
- 模型类标签：置信度 = 模型预测概率 / 校准后的概率
- 融合标签：多证据加权（如「吸筹」= 量价证据 0.6 + 资金证据 0.3 + 拆单证据 0.1）

**置信度必须校准**（Platt scaling / isotonic regression），否则不同标签的置信度不可比。

### 6.5 多重归属与冲突消解

- **允许并存**：一只股票可同时是「成长」+「价值」（连续暴露度上的不同位置），不必强制互斥。
- **互斥标签**：趋势状态（6 阶段）在同一时点**必须互斥**（只能一个状态），这是唯一需要强制互斥的域。
- **冲突处理**：当多证据冲突时（如量价显示吸筹但资金显示派发），输出主标签 + 冲突标记，交由上层决定，而非静默覆盖。

### 7.2 存储选型（多标签筛选的性能关键）

| 方案                                                                             | 适用       | 优势            | 建议             |
| ------------------------------------------------------------------------------ | -------- | ------------- | -------------- |
| **Postgres 关联表**                                                               | 标签主存储    | 已有基础设施、事务、易维护 | ✅ 主存储          |

- 主存储：Postgres（`stock_tags` 表 + GIN 索引 + 分区）

- 回测：Parquet 列存快照

### 7.3 多标签筛选查询设计

**查询 DSL 示例**：

```json
{
  "market": ["HK"],
  "industry_sw1": ["医药生物"],
  "type": ["创新亏损高增长"],
  "stage": ["低位吸筹", "拉升初期"],
  "southbound": ["连续增持"],
  "min_confidence": {"stage": 0.6},
  "exclude": {"event_risk": ["解禁临近"]},
  "as_of_date": "2026-09-01"
}
```

**执行逻辑**：

1. 每个标签条件 → 股票 ID 位图（从 ES 或位图缓存取）
2. 位图按 AND / OR / NOT 做集合运算
3. 置信度过滤
4. `as_of_date` → 走快照表取历史标签（回测用）
5. 返回股票列表 + 命中标签明细

### 7.4 计算与更新调度

| 事件风险               | 实时   | 公告流监听           |

**增量计算**：只重算当日有数据变化的股票（如当日有行情的），大幅降低计算量。

## 8. 标签质量治理与验证

### 8.1 质量指标

| 指标  | 定义             | 目标                    |
| --- | -------------- | --------------------- |
| 覆盖率 | 有该标签的股票占比      | 描述性标签 >95%，判断性标签 >80% |
| 准确率 | 人工抽检正确率        | 规则类 >98%，模型类 >80%     |
| 稳定性 | 相邻日标签翻转率       | 日频标签 <5%/日            |
| 时效性 | 数据到标签的延迟       | T+0 2h 内              |
| 区分度 | 标签分组间前瞻收益差异显著性 | t 检验 p<0.05（判断性标签）    |
| 一致性 | 与人工/外部标签的一致率   | >85%                  |

### 8.2 验证方法

| 标签类型           | 验证方式                             |
| -------------- | -------------------------------- |
| 规则类（①⑪）        | 单元测试 + 人工抽检 + 边界案例               |
| 统计分位类（②③④⑤⑥⑦⑨） | 分布检查 + 跨期稳定性 + 极端值检查             |
| 模型类（⑩⑫）        | **前瞻收益验证** + 聚类一致性 + 人工抽检 + 研报校准 |
| 外部映射类（①⑧）      | 与外部源交叉核对 + 缺失率监控                 |

### 8.3 标签快照与时间旅行（回测必需）

**这是最容易被忽略、但决定系统价值上限的能力。**

- `stock_tags` 表设计 `eff_from` / `eff_to` 双时间戳，标签变更不覆盖而是新增版本
- 查询时按 `as_of_date` 取当时有效的标签版本
- 回测时严格按 PIT 取标签，杜绝前视偏差
- 建议每月/每日生成标签快照落 Parquet，供回测批量加载

### 8.4 标签血缘与版本

- 每个标签记录：计算脚本版本、模型版本、依赖数据版本
- 标签口径变更时发新版本，旧版本保留（保证历史回测可复现）
- 提供血缘查询：某标签 ← 哪些特征 ← 哪些源表

## 13. 结论与建议

### 13.1 可行性结论

**项目整体可行，建议立项。**

- **需求明确且合理**：多标签画像是「多维筛选」场景的正确范式，显著优于单一打分。
- **数据基础扎实**：量价 + 基本面 2019-now 全量，足以支撑核心趋势状态标签的训练与验证；部分外部数据缺口可通过降级方案或后续采购解决。
- **技术方案成熟**：多标签存储与检索是业界已大规模验证的问题（用户画像/DMP 领域），方案明确、风险可控。
- **主要难点可控**：趋势状态标签无 ground truth 是真实挑战，但「无前视定义 + 前瞻验证」的闭环路径清晰可行。

### 13.2 三条核心建议

1. **立即接受「标签需要迭代」这一前提**。不要在 P2 阶段追求阶段标签的完美，先跑通闭环、拿到第一份「各阶段前瞻收益分布」报告，再迭代。这是本项目能否推进的关键心态。
2. **优先建设 PIT 与快照能力（不要拖到 P6）**。虽然路线图中排在后面，但 `eff_from/eff_to` 的表设计必须在 P0 就定好。事后补快照能力代价极大——这是业界画像系统最常踩的坑。
3. **严格区分蓝域与橙域的资源投入**。蓝域（①-⑨、⑪，描述性标签）是确定性工程，可快速批量完成；橙域（⑩ 趋势状态、⑫ 预测评分，判断性标签）是研究性问题，需要验证闭环与迭代。把两者混在一起做，会导致项目在橙域上卡死而蓝域也没产出。
4. **标签术语独立于 Barra，不追求对齐**。⑦ 交易特征只保留纯量价派生的统计暴露，Value / Growth / Quality 归入基本面域 ③④⑤。后续若做风险归因，单独建映射表维护，不让风险模型的口径污染标签体系。

### 13.3 下一步行动

1. 确认首期范围（建议 P0-P3）
2. 确认数据源接入方式（Postgres 直连 vs 本地文件）
3. 确认股票池范围（全市场 vs 限定池）
4. 启动 P0：标签元数据模型 + `stock_tags` 表设计

**蓝域（①-⑨、⑪）为描述性标签，可规则化、风险低；橙域（⑩⑫）为判断性标签，无 ground truth、需验证闭环，风险高——这是资源分配的根本依据。**

> **术语独立性说明**：本体系的域划分**不与 Barra 因子体系强制对齐**。Barra CNE6 将 Value / Growth / Quality 也称为「风格因子」，但其输入是财务数据；本体系中这些归入基本面域（③④⑤），**⑦ 交易特征只保留纯量价派生的统计暴露**。理由是：Barra 是**风险模型**（目的是解释收益协方差），画像是**描述体系**（目的是多维刻画与筛选），目的不同不可照搬。若后续需做风险归因，应**单独建立映射表**维护，不污染标签体系。

**③④⑤ 三域的分界（最易混淆，务必按此判定）**：

1. 先问**是否含价格** → 含价格且分母为经营基本面 = ③ 估值水平；
2. 不含价格（纯财报）再问**是水平还是变化率** → 水平 / 比率 = ④ 盈利质量；变化率 / 投入强度 = ⑤ 成长特征；
3. **股息率、分红率例外**：属分配行为而非经营基本面，归 ⑥ 股东回报。


### 4.3 各域标签清单（首期建议）

#### ① 证券属性（12 个）

**定义**：描述证券的**静态登记与归属**，回答「这是什么证券、在哪交易、属于哪个官方分类」。  
**判定标准**：取值由交易所规则、监管分类、公司注册信息决定，**与股价、成交量、财务表现均无关**——这是它与其余所有域的根本分界。

| 标签          | 取值                           | 来源   |
| ----------- | ---------------------------- | ---- |
| 市场          | A股 / 港股                      | 基础   |
| 交易所与板块      | 主板/创业板/科创板/北交所/港股主板/港股创业板    | 基础   |
| 证券类型        | 普通股 / 优先股 / 存托凭证(DR) / B股    | 基础   |
| 地域          | 注册地、办公地（省/市）                 | 基础   |
| 所有制         | 国资 / 民营 / 外资                 | 外部   |
| 上市年限档       | 次新(<1y) / 成熟(1-5y) / 老股(>5y) | 规则   |
| 申万一级行业      | 31 类                         | 外部标准 |
| 申万二级 / 三级行业 | —                            | 外部标准 |
| GICS 行业     | 可选，用于跨市场对比                   | 外部标准 |
| 是否多地上市      | A+H 同时上市                     | 规则   |

> **移出项**：市值档、指数成分、港股通标的 → ② 规模属性（时变量，非静态身份）；ST / 退市 → ⑪ 事件风险（风险状态）。  
> **行业 vs 概念**：行业是**官方标准分类**（单一层级归属、稳定），在本域；概念是**市场约定叙事**（多重归属、动态），在 ⑧ 题材概念。

#### ② 规模属性（8 个）

**定义**：描述公司在**资本市场的体量**，回答「有多大」。  
**判定标准**：由市值、营收、资产规模派生；**时变量**（随股价与财报变化），故与 ① 证券属性（准静态）分离。

| 标签      | 取值                                   | 说明        |
| ------- | ------------------------------------ | --------- |
| 总市值档    | 特大 / 大 / 中 / 小 / 微                   | 横截面分位     |
| 自由流通市值档 | 五档                                   | 剔除限售与控股部分 |
| 营收规模档   | 五档                                   | 行业内分位更可比  |
| 总资产规模档  | 五档                                   | —         |
| 行业规模排名  | 具体排名                                 | 龙头识别      |
| 指数成分    | 沪深300 / 中证500 / 中证1000 / 上证50 / 恒生系列 | 外部        |
| 港股通标的   | 布尔                                   | 外部        |

> **说明**：指数成分与港股通资格，是指数编制规则对「规模 + 流动性」的**官方认定结果**，故归入本域而非 ① 或 ⑦。

**双轨设计**：上述标签同时保留**连续值**（供研究/回测）与**分档标签**（供筛选）。

#### ③ 估值水平（10 个）

**定义**：描述**价格相对于公司经营基本面**的贵贱，回答「贵还是便宜」。  
**判定标准**：计算形如「股价或市值 ÷ 经营基本面指标（盈利 / 资产 / 销售 / 现金流）」及其倒数。**分母必须是经营基本面**——这是它与 ⑥ 股东回报的根本分界。

> **PS/PCF 口径：只算一处（2026-09 起）**
> 行情表**不存** `ps_ttm_ratio` / `pcf_ttm_ratio` 这类派生列。背景：外部源不提供 PS/PCF，
> 曾由「东财直采（A 股）+ 本地推算（港股）+ 采集脚本钩子」三路分别写表，其中港股一路把
> 累计口径的 Q1/H1/Q3/annual 直接求和（`SUM(近4期)`），分母虚高约 **2.4 倍**、
> 取 A 股对照东财 PS 得比值恒为 **0.42**；且该列日常链路填不满，导致 PS/PCF 标签有效行数一度为 0。
> 现收敛为单一实现：
> - 分子 = 行情表 `total_market_val`（外部源直供、日采必写）；
> - 分母 = `profiling.quantile.load_financial_ttm`（滚动 12 个月的营收 / 经营现金流 / 净利，
>   **全仓唯一实现**，PS/PCF/PEG 共用；公式 `TTM = 本期累计 + 上年全年 − 上年同期累计`，
>   校验：对标东财 PS 比值中位 1.000、94.2% 误差 <5%）。
> 标签层只引用该 helper，不再自带公式；回填脚本回归「补外部缺失原值」职责。

| 标签          | 说明              |
| ----------- | --------------- |
| PE(TTM) 档   | 市值 / 净利润        |
| PB 档        | 市值 / 净资产        |
| PS 档        | 市值 / 营业收入       |
| PCF 档       | 市值 / 经营现金流      |
| PEG 档        | PE(TTM) / 净利 TTM 同比增速，行业内排位（历史口径，非一致预期） |
| EV/EBITDA 档 | 含债口径，跨行业可比性更好   |
| FCF 收益率档    | 自由现金流 / 市值      |
| AH 溢价率      | A 股相对 H 股的估值差   |
| 估值历史分位      | 个股自身历史区间的分位（时序） |
| 估值行业分位      | 同行业内的横截面分位      |

> **必须双分位**：不同行业估值中枢差异极大，只给历史分位或只给行业分位都会误导，两者需并存。

#### ④ 盈利质量（12 个）

**定义**：描述**公司本身的经营品质**，回答「这是不是一门好生意」。  
**判定标准**：**全部来自财报三表，不含价格**，且描述的是**水平 / 比率**（非变化率）——这是它与 ③ 估值、⑤ 成长的双重分界。

| 标签           | 说明                         |
| ------------ | -------------------------- |
| ROE 档、ROIC 档 | 盈利能力核心指标                   |
| 毛利率档、净利率档    | 盈利空间                       |
| ROE 稳定性      | 近 3 年 ROE 波动率，**质量的核心是稳定** |
| 盈利真实性        | 经营现金流 / 净利润、应计项目占比（识别纸面利润） |
| 财务稳健性        | 资产负债率、有息负债率、利息保障倍数         |
| 资产效率         | 总资产周转率、应收 / 存货周转           |
| 连续盈利年数       | —                          |
| 营运资本异常       | 存货 / 应收周转显著恶化              |

> **说明**：杠杆与财务健康属本域（属财务特征），不再作为「风格因子」重复出现——这与 MSCI Quality 指数的定义一致（高 ROE + 低杠杆 + 盈利稳定）。

#### ⑤ 成长特征（9 个）

**定义**：描述公司**规模扩张的速度与投入方向**，回答「长得快不快、增长从哪来」。  
**判定标准**：来自财报的**变化率**（增速）与**投入强度**；**不含价格**。

| 标签                | 说明                   |
| ----------------- | -------------------- |
| 营收增速档、净利增速档、扣非增速档 | 三者需并存（扣非可识别非经常性损益粉饰） |
| 成长持续性             | 连续 N 期正增长            |
| 成长加速度             | 增速的二阶变化（加速 / 减速）     |
| 成长来源              | 内生增长 / 并购驱动          |
| 研发费用率档            | 投入强度                 |
| 资本开支强度档           | 扩张意愿与行业属性            |
| 员工规模增速            | —                    |

> **成长与质量是两个独立维度**：高增长低质量（烧钱扩张）与低增长高质量（现金牛）都是常见且有效的组合，**不可混为一谈**。

#### ⑥ 股东回报（6 个）

**定义**：描述公司**向股东返还现金的方式与力度**，回答「股东能拿回多少」。  
**判定标准**：分红与回购相关，属**分配行为**而非经营基本面。

| 标签        | 说明                           |
| --------- | ---------------------------- |
| 股息率档      | 每股股息 / 股价（含价格，但回答「回报」而非「贵贱」） |
| 分红率档（派息率） | 分红 / 净利润，**不含价格**            |
| 连续分红年数    | 分红纪律                         |
| 分红增长性     | 股息的持续增长能力                    |
| 回购力度      | 回购金额 / 市值                    |
| 股东回报率     | （分红 + 回购）/ 市值                |

> **划归依据**：分红率不含价格，按定义不属于 ③ 估值；股息率虽含价格，但回答的是「回报多少」而非「贵不贵」。红利 / 高股息是 A 股与港股的一等筛选维度（红利策略、恒生高股息），故独立成域以便检索。

#### ⑦ 交易特征（9 个）

**定义**：描述股票在**交易行为层面**呈现的统计特征与风险暴露，回答「它怎么被交易、波动特性如何」。  
**判定标准**：由**行情数据（价格、成交量）的统计特征**计算，**不含任何财务数据**；采用**横截面分位**（同日全市场比较）。

| 子组  | 标签                        | 说明         |
| --- | ------------------------- | ---------- |
| 趋势性 | 动量档（12-1 月）、反转档（1 月）      | 方向性统计特征    |
| 波动性 | 年化波动率档、Beta 档、残差波动档、下行波动档 | 波动与系统性风险暴露 |
| 活跃度 | 流动性档（日均成交额 / Amihud）、换手率档 | 好不好买卖、交易热度 |
| 风险  | 最大回撤档                     | 极端下跌风险     |

> **与 ⑩ 趋势状态的分工**：⑦ 是**横截面统计暴露**（不互斥、确定性、无需验证）；⑩ 是**时序状态机**（互斥、判断性、需验证闭环）。⑩ 的判定不读取 ⑦ 的分档结果，两者交叉组合产生增量筛选价值。

#### ⑧ 题材概念（10 个）

- 概念板块标签（同花顺/东财概念体系，多重归属）
- 产业链位置（上游/中游/下游）
- 政策主题（如「专精特新」「国产替代」「出海」）
- 热点关联度（当前市场热点匹配度，日频）
- 题材纯度（主营与概念的匹配程度）

> **注意**：概念标签是**多重归属**的，一只股票可同时挂 5-20 个概念。且概念有热度与时效性，需带「热度分」与「生效/失效时间」。

#### ⑨ 资金关注度（15 个）

- 北向/南向持股占比档、连续增减持天数
- 主力资金净流入档（日/5日/20日）
- 机构持仓变化、基金重仓
- 融资融券余额变化
- 股东户数变化（减少=筹码集中）
- 龙虎榜出现频率、游资/机构席位
- 研报覆盖度、评级变化
- 成交量能异常（放量/缩量）

#### ⑩ 趋势状态（判断性标签，分期建设）

**建设顺序（2026-09 更新）**：本域是唯一需要「无前视定义 + 前瞻收益验证」闭环的橙域，6 阶段状态机短期无法收敛，故**先落共享的位置要素，再落状态机**：

| 顺序 | 标签 | 性质 | 状态 |
| -- | ---- | ---- | ---- |
| 1 | 股价52周位置档 `tst_price_position_52w` | 确定性要素（位置） | ✅ 已实现 |
| 2 | 趋势阶段 `tst_stage` | 判断性状态机（6 阶段） | ⏳ 待建：需 t+20 / t+60 前瞻收益验证闭环 |

先落位置档的理由是双重的：① 让本域立刻可用——已可独立筛选，也可与其他域交叉；② 6 阶段定义里各自重复的「价格分位<30% / >80%」阈值有了统一口径来源，避免将来各写一套。

##### 10.1 股价52周位置档 `tst_price_position_52w`

| 项目 | 说明 |
| ---- | ---- |
| 计算口径 | 位置 = (收盘价 − 窗口最低价) / (窗口最高价 − 窗口最低价) × 100，落在 0-100 |
| 窗口 | 截至 as_of 的近 **252 个交易日**（与 ⑦ 同为交易日口径）；最高/最低取日内 high / low，收盘取当日 close |
| 取值 | 1=[0,20) 贴近 52 周低点；2=[20,40)；3=[40,60)；4=[60,80)；5=[80,100] 贴近 52 周高点 |
| 双轨 | `num_value` 保留连续位置值（0-100），分档不丢精度 |
| 数据来源 | `a_daily_quote` / `hk_daily_quote`（high / low / close） |
| 更新频率 | 日 |
| PIT | 是（仅用 t 及之前的量价，任意历史 as_of 可回溯） |

**三条关键口径决定**：

1. **用个股自身区间的绝对分档，不做市场内五等分**。本域判定标准是「个股跟自己历史比」，做成横截面就退化成 ⑦ 的口径了；且绝对分档的**分布偏斜本身就是市场状态信号**——2026-09 全市场多数落在 1-2 档，2025-09 则多数落在 4-5 档，横截面五等分会强制把这一信息抹平。
2. **窗口自己回算，不读 `high_52w` / `low_52w` 快照列**。该列在 `hk_daily_quote` 覆盖 100%，但在 `a_daily_quote` 仅回填最近十余个交易日（历史覆盖≈0）。直接读会让本标签在今天看起来完全正常，却在绝大部分历史日期静默产出空值、直到回测才暴露。自己按 252 个交易日回算则任意历史 as_of 都成立（实测与供应商快照列位置差中位数 0.09pp，残余差异来自「252 交易日 vs 自然 52 周」口径）。
3. **不做「满 52 周」覆盖率门槛**：上市不足一年的股票（如 `HK.02513` 窗口内仅 165 行）也照常出值，用其窗口内可用历史区间计算位置。本标签定位是「看股价处于自身历史区间的哪一段」，而非严格的 52 周统计；与个股概览页（直接用 `high_52w`/`low_52w` 快照列、不过滤）同口径，过滤太严会让大量次新/近期上市股丢失该标签、与页面显示不一致。

   **仅剔除退化/空值样本**：区间须有真实宽度（`high > low`，单日股 `high==low` 自然排除）、端点为正、收盘为正；无需额外的「新鲜度」门槛，停牌几天仍保留、长期退市者因无有效行自然排除。

   **先剔除坏快照行再算极值**：港股行情存在 `high=0, low=0` 的脏数据（占比约 2.2%、波及半数港股），若直接取 `min(low)` 会让单条 0 毒化整只股票。故先过滤 `high/low/close ≤ 0` 与 `high < low` 的行，再算区间高点/低点。

> **它能替代 6 阶段状态机吗？不能。** 位置档回答「处在自身 52 周区间的哪一段」，是**位置**；阶段回答「处在趋势的哪个阶段」，是**状态**。贴近 52 周高点的标的可能是主升途中，也可能是深跌后刚反弹——位置相同而性质相反，区分它们正是 6 阶段状态机要做的事。正确用法是与其他域交叉：如「位置档 1 + 南向连续增持」= 左侧布局候选；「位置档 5 + 高位派发」= 强弩之末。

##### 10.2 趋势阶段（6 阶段状态机，待建）

| 标签值    | 可观测定义（仅用 t 及之前）                                   |
| ------ | ------------------------------------------------- |
| 低位吸筹   | 价格分位<30%；量能温和放大(1.2~2×)但价平；波动收敛；资金净流入             |
| 拉升初期   | 突破 60 日平台；放量(>1.5×)；MA20 上穿 MA60；相对强度由负转正；分位仍<60% |
| 上升趋势确认 | MA 多头排列；回踩不破 MA20；相对强度持续为正；量能稳定                   |
| 高位派发   | 分位>80%；放量滞涨/长上影；换手率同类型分位极高；资金净流出                  |
| 下跌     | 空头排列；反弹不过前高；相对强度为负                                |
| 震荡     | 区间宽度<阈值；均线缠绕；波动率低；相对强度≈0                          |

> **三条关键约束**：
>
> 1. 该标签**必须同类型 / 同行业内相对化**（题材股换手率天然高）。
> 2. **判定用个股时序分位**（自己跟自己历史比），而非 ⑦ 交易特征的横截面分位——两者虽都叫「波动率 / 动量」，但计算口径完全不同。
> 3. **必须从原始量价直接计算，不读取 ⑦ 的分档标签**——避免信息损失、口径错配与版本耦合。

> **与 ⑦ 交易特征的关系**：不冲突，是两个抽象层。⑦ 是「要素测量」（温度/湿度/风速，横截面统计暴露、不互斥、确定性）；⑩ 是「状态判断」（晴/雨/多云，时序状态机、互斥、需验证）。两者交叉组合产生增量信息——如「高动量 + 拉升初期」= 强势启动，「高动量 + 高位派发」= 强弩之末。

#### ⑪ 事件风险（22 个）

财报披露临近/超预期/低于预期、业绩预告、大股东增减持、解禁临近、股权质押比例高、商誉减值风险、诉讼/监管问询、ST 风险、退市风险、停牌、可转债/再融资、管理层变动、审计意见异常。

#### ⑫ 预测评分（4 个，判断性，需严格验证）

拥挤度档、预期收益档、风险预警档。

> **建议**：首期只做「拥挤度」与「趋势状态置信度」，其余预测性标签待验证体系成熟后再上。

### 5.2 关键数据风险与对策

| 风险              | 影响                         | 对策                            |
| --------------- | -------------------------- | ----------------------------- |
| **前视偏差（PIT）**   | 财报按报告期而非**实际披露日**入库 → 回测虚高 | **必须建立 PIT 数据库**：财务数据以实际披露日生效 |
| **幸存者偏差**       | 只含现存股票 → 回测虚高              | 股票池必须**包含已退市股票**及其历史数据        |

| **行业分类变更**      | 历史行业归属变化                   | 行业标签需带生效时间，按 PIT 取用           |
| **资金/拆单仅近期**    | 无法长历史验证                    | 作为增强标签，明确标注数据起点               |
| **概念/事件数据外采成本** | 预算与合规                      | 首期可先用简化版（自建关键词匹配），后期评估采购      |

### 5.3 数据可得性结论

**核心结论：⑦ 交易特征 与 ⑩ 趋势状态 的数据基础（量价 2019-now 全量）最扎实，应优先建设。** ①②④⑤ 依赖外部标准数据与财报，补齐成本可控；③ 需财报 PIT 支持；⑥⑧⑨⑪ 存在真实缺口，建议首期用简化方案或延后。

## 6. 标签生成方法（算法可行性）

### 6.1 四类生成方式

| 方式            | 适用                         | 优点         | 缺点        |
| ------------- | -------------------------- | ---------- | --------- |
| **规则/阈值**     | 证券属性、事件风险、部分盈利质量           | 可解释、确定、零训练 | 覆盖不全、阈值需调 |
| **统计/分位**     | 规模、估值、盈利质量、成长、股东回报、交易特征、资金 | 跨期可比、自适应   | 需足够横截面样本  |
| **模型（分类/聚类）** | 趋势状态、题材概念、预测评分             | 泛化、能发现新模式  | 需验证、可解释性弱 |
| **外部映射**      | 行业、概念、评级                   | 权威、省事      | 依赖外部、成本   |

| ⑦ 交易特征  | 横截面分位（保留连续暴露度）    | 聚类验证分档合理性            |

| ⑫ 预测评分  | 监督模型（严格时序 CV）     | 首期限保守范围              |

### 6.3 趋势状态标签的专门方案（核心难点）

趋势状态（吸筹/拉升/派发…）**没有 ground truth**，这是本项目最大的算法挑战，也是「标注悖论」的正面战场。可行路径：

```
① 可观测结构（t 及之前的量价/资金）
        ↓  规则定义（无前视）
② 阶段标签
        ↓  前瞻收益验证（t+20 / t+60）
③ 有效性检验：各阶段前瞻收益是否显著分离且方向符合预期
        ↓  不通过则回改规则
④ 迭代至收敛 → 得到可信标签集
        ↓
⑤ 蒸馏为监督模型（LightGBM），严格时序切分
        ↓
⑥ HMM 无监督状态发现作交叉验证
   （一致 → 规则可信；不一致处 → 潜在新模式）
```

**关键方法论**：阶段标签的**定义不依赖未来**，但**验证使用未来**。这打破了「用未来定义吸筹 → 循环论证」的悖论。这是业界处理无监督状态标注的标准思路（定义与验证分离）。

**训练要点**：

- 样本 =（股票, 日期）；特征只用 t 及之前
- 严格时序切分：train 2019-2022 / val 2023-2024 / test 2025-2026
- 扩样窗口 CV + `GroupKFold(by stock)` 防同股泄露
- 类别不平衡（震荡/下跌占比高）→ `class_weight='balanced'`
- 软标签：边界样本用 HMM 后验概率，或标「过渡」
- **前瞻收益绝不进特征**

**验证要点**：

- 各阶段 t+20/t+60 前瞻收益的均值/中位数/胜率 + t 检验（第一道关）
- 转移矩阵合理性（吸筹→拉升、拉升→派发概率）
- 类型 × 阶段 分层回测
- Regime 稳定性（牛/熊/震荡分段）
- 人工抽检 + 研报素材校准

### 6.4 标签置信度

模型类标签（⑩⑫）必须输出置信度，供筛选时加权或过滤：

- 规则类标签：置信度 = 1.0（确定性）
- 统计分位类：置信度 = 1.0（确定性，但可标注样本量）
- 模型类标签：置信度 = 模型预测概率 / 校准后的概率
- 融合标签：多证据加权（如「吸筹」= 量价证据 0.6 + 资金证据 0.3 + 拆单证据 0.1）

**置信度必须校准**（Platt scaling / isotonic regression），否则不同标签的置信度不可比。

### 6.5 多重归属与冲突消解

- **允许并存**：一只股票可同时是「成长」+「价值」（连续暴露度上的不同位置），不必强制互斥。
- **互斥标签**：趋势状态（6 阶段）在同一时点**必须互斥**（只能一个状态），这是唯一需要强制互斥的域。
- **冲突处理**：当多证据冲突时（如量价显示吸筹但资金显示派发），输出主标签 + 冲突标记，交由上层决定，而非静默覆盖。

### 7.2 存储选型（多标签筛选的性能关键）

| 方案                                                                             | 适用       | 优势            | 建议             |
| ------------------------------------------------------------------------------ | -------- | ------------- | -------------- |
| **Postgres 关联表**                                                               | 标签主存储    | 已有基础设施、事务、易维护 | ✅ 主存储          |
| `stock_tags(stock_id, tag_code, value, confidence, eff_from, eff_to, version)` | —        | 天然支持快照回溯      | ✅              |
| GIN 索引 / 部分索引                                                                  | 单标签过滤    | 简单场景够用        | ✅ 辅助           |
| **Elasticsearch 倒排**                                                           | 复杂多条件筛选  | 多条件组合、分词、排序   | 推荐（标签数 >100 时） |
| **RoaringBitmap 缓存**                                                           | 高频固定组合查询 | 交并差毫秒级        | 推荐（热标签缓存）      |
| **图数据库 (Neo4j)**                                                               | 产业链/概念关联 | 关系查询          | 后期按需           |
| **Parquet / 列存**                                                               | 回测批量取标签  | 扫描快           | 推荐（回测用）        |

**推荐组合**：

- 主存储：Postgres（`stock_tags` 表 + GIN 索引 + 分区）
- 在线筛选：ES 倒排（复杂组合）+ RoaringBitmap 缓存（热标签）
- 回测：Parquet 列存快照

### 7.3 多标签筛选查询设计

**查询 DSL 示例**：

```json
{
  "market": ["HK"],
  "industry_sw1": ["医药生物"],
  "type": ["创新亏损高增长"],
  "stage": ["低位吸筹", "拉升初期"],
  "southbound": ["连续增持"],
  "min_confidence": {"stage": 0.6},
  "exclude": {"event_risk": ["解禁临近"]},
  "as_of_date": "2026-09-01"
}
```

**执行逻辑**：

1. 每个标签条件 → 股票 ID 位图（从 ES 或位图缓存取）
2. 位图按 AND / OR / NOT 做集合运算
3. 置信度过滤
4. `as_of_date` → 走快照表取历史标签（回测用）
5. 返回股票列表 + 命中标签明细

### 7.4 计算与更新调度

| 标签类型               | 频率   | 触发              |
| ------------------ | ---- | --------------- |
| 趋势状态、资金关注度、预测评分    | 日频   | 收盘后定时（T+0 2h 内） |
| 风格、关注度             | 周/月频 | 定时任务            |
| 盈利质量 / 成长特征 / 股东回报 | 季频   | 财报披露事件驱动        |
| 身份、题材              | 事件驱动 | 分类调整/概念更新       |
| 事件风险               | 实时   | 公告流监听           |

**增量计算**：只重算当日有数据变化的股票（如当日有行情的），大幅降低计算量。

## 8. 标签质量治理与验证

### 8.1 质量指标

| 指标  | 定义             | 目标                    |
| --- | -------------- | --------------------- |
| 覆盖率 | 有该标签的股票占比      | 描述性标签 >95%，判断性标签 >80% |
| 准确率 | 人工抽检正确率        | 规则类 >98%，模型类 >80%     |
| 稳定性 | 相邻日标签翻转率       | 日频标签 <5%/日            |
| 时效性 | 数据到标签的延迟       | T+0 2h 内              |
| 区分度 | 标签分组间前瞻收益差异显著性 | t 检验 p<0.05（判断性标签）    |
| 一致性 | 与人工/外部标签的一致率   | >85%                  |

### 8.2 验证方法

| 标签类型           | 验证方式                             |
| -------------- | -------------------------------- |
| 规则类（①⑪）        | 单元测试 + 人工抽检 + 边界案例               |
| 统计分位类（②③④⑤⑥⑦⑨） | 分布检查 + 跨期稳定性 + 极端值检查             |
| 模型类（⑩⑫）        | **前瞻收益验证** + 聚类一致性 + 人工抽检 + 研报校准 |
| 外部映射类（①⑧）      | 与外部源交叉核对 + 缺失率监控                 |

### 8.3 标签快照与时间旅行（回测必需）

**这是最容易被忽略、但决定系统价值上限的能力。**

- `stock_tags` 表设计 `eff_from` / `eff_to` 双时间戳，标签变更不覆盖而是新增版本
- 查询时按 `as_of_date` 取当时有效的标签版本
- 回测时严格按 PIT 取标签，杜绝前视偏差
- 建议每月/每日生成标签快照落 Parquet，供回测批量加载

### 8.4 标签血缘与版本

- 每个标签记录：计算脚本版本、模型版本、依赖数据版本
- 标签口径变更时发新版本，旧版本保留（保证历史回测可复现）
- 提供血缘查询：某标签 ← 哪些特征 ← 哪些源表

## 13. 结论与建议

### 13.1 可行性结论

**项目整体可行，建议立项。**

- **需求明确且合理**：多标签画像是「多维筛选」场景的正确范式，显著优于单一打分。
- **数据基础扎实**：量价 + 基本面 2019-now 全量，足以支撑核心趋势状态标签的训练与验证；部分外部数据缺口可通过降级方案或后续采购解决。
- **技术方案成熟**：多标签存储与检索是业界已大规模验证的问题（用户画像/DMP 领域），方案明确、风险可控。
- **主要难点可控**：趋势状态标签无 ground truth 是真实挑战，但「无前视定义 + 前瞻验证」的闭环路径清晰可行。

### 13.2 三条核心建议

1. **立即接受「标签需要迭代」这一前提**。不要在 P2 阶段追求阶段标签的完美，先跑通闭环、拿到第一份「各阶段前瞻收益分布」报告，再迭代。这是本项目能否推进的关键心态。
2. **优先建设 PIT 与快照能力（不要拖到 P6）**。虽然路线图中排在后面，但 `eff_from/eff_to` 的表设计必须在 P0 就定好。事后补快照能力代价极大——这是业界画像系统最常踩的坑。
3. **严格区分蓝域与橙域的资源投入**。蓝域（①-⑨、⑪，描述性标签）是确定性工程，可快速批量完成；橙域（⑩ 趋势状态、⑫ 预测评分，判断性标签）是研究性问题，需要验证闭环与迭代。把两者混在一起做，会导致项目在橙域上卡死而蓝域也没产出。
4. **标签术语独立于 Barra，不追求对齐**。⑦ 交易特征只保留纯量价派生的统计暴露，Value / Growth / Quality 归入基本面域 ③④⑤。后续若做风险归因，单独建映射表维护，不让风险模型的口径污染标签体系。

1. 确认首期范围（建议 P0-P3）
2. 确认数据源接入方式（Postgres 直连 vs 本地文件）
3. 确认股票池范围（全市场 vs 限定池）

## 附录 B：关键技术术语

| 术语                  | 说明                                                             |
| ------------------- | -------------------------------------------------------------- |
| PIT (Point-in-Time) | 按数据实际披露时间而非报告期记录，防止前视偏差                                        |
| 幸存者偏差               | 只统计现存标的导致的回测虚高                                                 |
| RoaringBitmap       | 高效压缩位图，用于多标签集合交并差运算                                            |
| 标签快照 / 时间旅行         | 可查询任意历史时点的标签状态                                                 |
| 标签血缘 (Lineage)      | 标签的计算来源、版本与依赖关系                                                |
| IC / ICIR           | 信息系数及其稳定性指标，用于单因子有效性检验                                         |
| 置信度校准               | 使模型输出概率与真实正确率一致（Platt/Isotonic）                                |
| Barra CNE6          | 中国市场主流风险模型（规模/价值/成长/质量/动量等风格因子）。**本标签体系术语不与其对齐**，见 4.2 术语独立性说明 |
| HMM                 | 隐马尔可夫模型，用于无监督时序状态发现                                            |
