## 0. 一句话定位

**市场画像 = 把 200+ 指标与公式判定，组织成一条「可反算、可溯源」的证据链让人自己读，而不是塞一个结论给人信。**

## 1. 设计目标与核心矛盾

### 1.1 要解决的问题
系统输出的是「判定」（夏 / 偏热 / 风险 53 / 信号 7/18），而 `market_profile.md` §8.5 自己承认：**状态判定没有 ground truth**，只能靠"规则 + 前瞻验证"闭环迭代。所以 UI 必须解决：**用户凭什么相信这个判定？**

### 1.2 设计目标
| 目标 | 手段 |
|---|---|
| 结论可被检验 | 每个判定都能展开看到它的**构成**与**来源** |
| 剔除"假精确" | 所有数字标注 **是否可反算**；不可反算的（宏观）改为标注**数据谱系** |
| 防止误读 | 时间尺度显式标注；市场口径显式标注；观点/事实视觉分层 |
| 可下钻到原始事实 | 三级结构，逐层展开到原始指标 |

## 2. 核心设计原则（6 条，硬规范）

### 2.1 证据先于结论
**趋势 + 历史分位是主视觉（大面积），判定只是旁注小标签。**
- ❌ 禁止把"结论带"放在页面最顶部先给答案。
- ✅ 正确顺序：市场条 → 切换提示 → 合成值 tab → **详情区（趋势/成分/证据）** → 规则说明 → 质疑入口。

### 2.2 三层结构 + 双校验路径
```
① 综合指数          （市场温度 57 / 风险指数 53 / 金融压力 41 / 季节 / 顶部信号）
   ↓ 必须可下钻
② 维度分 / 原始指标  （估值 62 / 情绪 74 / 压力 41 …）
   ↓ 必须可下钻
③ 原始指标层        （PE 中位数 / VHSI / 社融 …）
```
| 页型 | ③ 层性质 | 校验方式 |
|---|---|---|
| **市场页** | 构成拆解 | **可反算**：③ 的分位等权平均 ≈ ② 的值 |
| **宏观页** | 数据谱系 | **可溯源**：每项标 分项 / 数据源 / 频率 / 发布滞后 |

> **红线**：任何 ② 的值必须能从 ③ 反算出来。反算不通 = 数字不可信 = 返工。

### 2.3 禁用单指标代表多输入判定
判定由 N 个输入决定，就必须让 N 个输入都能被看到。
> 反例（已修正）：用一个「全市场 PE」大图代表"季节"——季节由 6 个输入共同决定（§8.1）。

### 2.4 时间尺度显式标注 + 禁止混读
| 尺度 | 含义 | 对应层 |
|---|---|---|
| **气候** | 数年 | ① 宏观 + ② 资产配置 |
| **季节** | 月-季-年 | ① 宏观周期 + ③ 估值/宽度趋势 |
| **天气** | 日-周 | ③ 情绪/资金/波动 |
- 每张卡、每个合成值、**每个成分**都要标尺度。
- 页面上常驻尺度图例，并写明警告：**「不可混用：用『天气』否定『季节』会频繁误判」**（§2.2）。

### 2.5 事实层 / 观点层视觉分层
| 层 | 内容 | 性质 |
|---|---|---|
| **事实层** | 当前值 + 趋势线 + **历史分位带**(min/25/50/75/max) + 数据截至 + 口径 | 不可辩驳 |
| **观点层** | 公式判定、季节判定 | **可辩驳**，必须标注公式来源，且允许被事实层推翻 |
- 观点标签统一后缀 **「· 公式判定」**。
- **禁止出现没有事实支撑的裸结论。**

### 2.6 可质疑、可覆盖
页面底部常驻 **「不认同某一判定？标注理由 ▾」**。用户标注即 ground truth，反哺 §8.5 的规则迭代闭环。

### 2.7 冷暖色阶与涨跌红绿解耦
- 涨跌：红涨 / 绿跌（`--up` / `--down`，中国习惯）。
- 分位/温度/风险等"冷热"刻度：**另起一套冷暖色阶**（冷蓝 `#8AB4D8` → 中性灰 → 暖橙 `#FF8800`），**不占用红绿**。
- 原因：避免"红"同时表示"涨"和"过热"。

## 3. 信息架构

### 3.1 三个页面（二级导航）
| 页面 | 定位 | 市场相关性 |
|---|---|---|
| **市场画像**（二级导航：港股市场 / A股市场） | 市场状态（③ 层为主） | **分市场，必须分开算** |
| **宏观环境**（二级导航独立项） | 全球宏观 **①**（数据文档 §3） | **市场无关，A股/港股共用输入** |
| **资产配置**（二级导航独立项，紧随宏观环境右侧） | 资产配置 **②**（数据文档 §4） | **市场无关，A股/港股共用输入** |

二级导航顺序：**`宏观环境` → `资产配置` → `港股市场` → `A股市场`**（当前页项用「胶囊 + 橙字 + 橙描边」激活态，其余为中性文字）。

> ⚠️ **A股 / 港股是「切换」不是「并排」**（§1.2 判断 4、§9.4：A/港口径混用 → 结论错误）。切换后整页重算。
> ⚠️ **宏观环境 / 资产配置不要和市场页签并列在"市场切换"里**——它们是环境层输入，不是第三个市场。（壳里已与市场项相邻但分属两类，实现时应做视觉或间距区分。）
> ① / ② 是**数据文档的层号**，不是页内分组序号：宏观页只有 ①，资产配置页只有 ②，两页各自的组标签保留原层号。

### 3.1.1 UI 文案禁用「气候 / 天气 / 季节」隐喻词（用户定，2026-10-09）

**UI 里不得出现「气候」「天气」「季节」及由它们派生的词**（含尺度标签、tab 后缀、成分卡后缀、图例、说明）。这三个词只作为**内部方法论口径**保留在本文档与数据文档中，**不面向用户显示**。

| 原 UI 文案 | 处理 |
|---|---|
| 详情头后的尺度标签（`气候` / `气候 + 天气`） | **删除该节点** |
| tab 名后缀（`经济周期定位 · 气候`） | 去掉后缀 → `经济周期定位` |
| `市场季节`（tab 名） | → **`市场周期`**（对应文档 §8.1「市场周期四阶段」） |
| `季节判定的输入` / `§8.1 季节判定` | → `周期判定的输入` / `§8.1 周期判定` |
| 成分卡后缀（`情绪 74（天气）`） | 去掉后缀 → `情绪 74` |
| 顶部信号分组（`季节 4：…` / `天气 3：…`） | → `结构信号 4 条：…` / `情绪信号 3 条：…` |
| 时间尺度图例行（`时间尺度：气候（数年）· 季节（月-季-年）· 天气（日-周）`） | **整行删除** |
| `本页为气候层：用于定方向与仓位中枢…` | → `本页用于定方向与仓位中枢，不可用于日频交易判断` |
| `不可混用：用「天气」否定「季节」会频繁误判` | → `不可混用：短期情绪波动不能用来否定中期趋势判断` |
| `季节划分的经典范式`（③ 层） | → `周期划分的经典范式` |

> **保留**：冬 / 春 / 夏 / 秋 四阶段名（它们是「市场周期四阶段」的阶段标签，不是被禁的三个词）。
> **内部保留**：下表「尺度」列仍标注气候/季节/天气，仅作**口径与设计依据**，**UI 不渲染**。

### 5.1.2b ② 层 «证据行»（v2，2026-10-09 样板于 经济周期定位）

**为什么改**：旧形态是「每个指标一张 96px 迷你折线卡」，存在三处硬伤 ——
① **编码错配**：比较任务用了「斜率编码」（Cleveland–McGill 感知精度排序中**最差档**），而应该用「长度编码」（精度仅次于位置）；
② **不可比**：迷你图**窗内自适应缩放** → 纵轴各异，**连斜率本身都不可比**；
③ **信噪比低**：每张 308×96 的底板只承载一条 1.8px 的线，**数据墨水比 ≈ 1%**，而 9 张占详情区 ~52% 面积。
④ **原理上做不到的任务**：文档 §8.2 的「多指标共振/背离」需要**同一坐标系**，分散的迷你图恰恰把坐标系拆散了。

**新形态（一行一指标，长度编码 + 共同基线）**：

| 列 | 宽 | 规格 |
|---|---|---|
| 指标名 | 300 | 12px SemiBold `--muted` |
| 当前值 | **150** | 13px Bold `--text` |
| **分位条** | fill（`layoutGrow:1`） | 24px 高 SVG：轨道 `#FFF@0.04` + 填充 `--accent`（宽 = 分位%） + 25/50/75 刻度细线 `#6B6B73` + 当前值标记（2px `--accent`）。**实测 790 宽** |
| **分位** | **66**（右对齐） | 12px Regular `--muted3`，如 `62%`。**格宽 66 = 文字 22 + 右侧 12 + 左侧留白 32** —— 左侧留白就是「分位条 ↔ 分位」的间距，靠"加宽 + 右对齐"实现（文本节点不支持 `paddingLeft`） |
| **方向** | **38**（**左对齐**） | 12px Regular `--muted3`，如 `↑ +6` / `↓ -8` / `→ 0`。**左对齐**让箭头左缘成列，`分位 ↔ 方向` 视觉间距仅 **12px**，两者读作一组 |

> **⭐ 列宽取值规则（用户定，2026-10-10）**：`指标名` / `当前值` / `分位·方向` 三列一律**按各列最长文本 + 16px 内边距**取值，**不用拍脑袋的固定数**；省下的宽度自动全部给 `分位条`（`layoutGrow:1`）。
> 本次实测收益：同样卡片宽度下 **分位条 644 → 790（+23%）**，两处空白（当前值列空 ≈140px、分位·方向列空 ≈138px）消失。
> 反例（已修）：分位·方向列曾固定 200px，而最长文本仅 ≈62px → **左侧 138px 纯空**，反倒把真正承载数据的分位条压窄了 —— 典型「空白挤占数据」。
| 表头 | — | 28px 高，11px `--muted2`，**五列逐一对齐**：`指标`(300) / `当前值`(150) / **分位刻度轴**(790 · SVG) / `分位`(34) / `方向`(38) |

> **⭐ 「分位」与「方向」必须是两个独立列，不能塞进一个字符串**（用户 2026-10-11 指出：前端拿到 `62%　↑ +6` 这种单字符串**无法实现两列对齐**，因为一个文本节点只能整体对齐、无法让「分位」右对齐到 A 列、「方向」右对齐到 B 列）。
> - 设计稿必须给出**两个独立元素 + 两个表头标签**（`分位` / `方向`），宽度分别固定 34 / 38，合计仍是原来的 84 → **分位条宽度不变（790）**。
> - **通用红线**：**凡是设计意图是"多列对齐"的地方，就不能用单个字符串拼版** —— 字符串只能整体对齐，无法分列。文字里用全角空格分隔（`分位　0 ── 25`）在实现端同样对不齐，必须改成多个元素 + 同 viewBox 的 SVG 刻度。
> - 「方向」格内的**箭头与数值不可再拆**（`↑ +6` 是一个语义单元，箭头必须紧贴数字）。

- 行高 **36px**，容器 `gap 6`，表头 28px。
- **⚠️ 表头的分位刻度必须用 SVG，不能用文本按字排**（用户 2026-10-10 报「分位和下方柱状图的刻度比例没对齐」）：纯文本 `分位　0 ── 25 ── 50 ── 75 ── 100` 在**比例字体**下字符位置与柱条实际刻度对不上，且列宽变化时更错位。
  ✅ **正确做法**：表头第 3 列放**与分位条同 viewBox（`0 0 644 24`）、同列宽（`layoutGrow:1`）的 SVG** —— 底部 1px 轴线 + 在 `0 / 161 / 322 / 483 / 643` 处的刻度线 + 数字（10px `--muted2`，居中于各自刻度；首尾贴边避免裁切）。因与各行分位条**同 viewBox 等比缩放**，**刻度与数字严格对齐**（实测：表头刻度轴与行内分位条同为 x=6704 / 宽 644）。
- **趋势不默认显示** —— 按 Shneiderman「Overview → Zoom/Filter → Details on demand」，单击某行再展开该指标的趋势 + 口径。
- 趋势只保留在 **① 主图**，且主图应支持**多指标叠加**（这才是看共振/背离的正解）。

**实测高度（诚实记录）**

| 项数 n | 旧（卡片网格，每行 4） | 新（证据行） | 差 |
|---|---|---|---|
| 6 | 298px（2 行） | 280px | **−18（−6%）** |
| **7** | **298px（2 行）** | **322px** | **+24（+8%）← 唯一略亏的档** |
| 9 | 453px（3 行） | 406px | **−47（−10%）** |

> 公式：新 = `28 + 42n`；旧 = `ceil(n/4)×143 + (ceil(n/4)−1)×12`。
> **n=7 吃亏的原因**：7 项在网格里只占 2 行（4+3），而证据行要 7 行 —— 行数换总高的临界点在 n≈6。
> 若在意这 24px，可调：行高 36→32、或表头并入首行 → `28+6+7×32+36 = 294px`，反超旧版。
> **结论**：高度不是本次改动的收益点；收益是**可比性、数据墨水比、认知成本**（9 次序列扫描 → 1 次前注意扫视）。

> **①↔② 归属规则（强制）**：文档某节的「方法/指标」表是**平铺列表**，UI 必须**逐行落到 ① 或 ②，不得漏项**。

### 12.3 已知坑（实现时避免）
- Ardot `content:` 内**全角逗号**会导致文本节点解析失败——属性分隔必须半角 `,`。
- Ardot 文本颜色必须用 `fills:[{type:"SOLID",…}]` 数组，**禁用 `fill:{r,g,b}` 对象**（会被静默丢弃 → 黑字）。
- 复制画板会把 `fill_container` 固化成固定 px，导致右侧元素被截断。
- **SVG 内文字禁止裸写 `<` / `>`**（如 `>80 狂热 / <20 恐慌`）——会被当作标签起始，整段 SVG 解析失败（报 `Failed to create svg`）。改用「80 以上 / 20 以下」或转义 `&lt;` `&gt;`。
- **SVG 直线（`<line>` 或直线的 `<path>`）包围盒有一维为 0 → 被判为不可见而丢弃**；直线一律用细长 `<rect>`（横线 `height=1`、竖线 `width=1`）。
- 卡内嵌图表用 `width:"fill_container"` + 固定 `height` + `viewBox`（等比缩放），**不要写死 px**，否则随列数/padding 变化而溢出。
- 查图表类节点的布局问题，`capture_layout` 的 `maxDepth` 必须 ≥ 5，否则只到 SVG 外壳、得到假阳性"无问题"。
- **`layout:"wrap"` 换行容器必须同时设 `height:"hug_contents"` + `clipsContent:false`**，否则容器高度仍按一行计算、第二行被裁切。
- **换行卡的固定宽度要按"最窄容器"取值**：同一组件在 1440 画板（行宽 1368）与页面（行号 1384）里可用宽度不同 → 4 卡满排的卡宽应取 **332**（4×332+36=1364，两种容器都放得下）；取 337 会在 1368 容器里退化成 3 卡/行。
- **SVG 内文字不认 `text-anchor`**：Ardot 解析时把 `x` 当**左原点**，`text-anchor="end"` 不生效 → 想右对齐必须自己减掉文字宽度（如 viewBox 宽 308、文字约 23 宽 → `x=284`）。否则文字会伸出 SVG 边界，被 `clipsContent` 裁掉（报 `OUTSIDE_PARENT`）。
- **迷你趋势图的 SVG viewBox 宽度要与卡内实际宽一致**（卡宽 332 − padding 24 = **308**），并用 `preserveAspectRatio="none"`；viewBox 与渲染宽度差太多会让折线斜率、文字横向被拉变形。
