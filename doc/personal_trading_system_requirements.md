## 0. 系统定位与建设目标

### 0.1 系统定位

这是一套**能够指导交易的辅助决策系统**：在每次交易前主动告诉我「现在该看什么、什么条件下可以动手、理由和赔率是多少」，而不是记录我做过什么。系统是决策生成者，记录与审计只是它的副产品。

| 维度 | 定位 |
|---|---|
| 主产出 | **带依据的个股推荐（决策卡 + 每日推荐清单）+ 时机窗口 + 赔率尺度 + 可展开依据链** |
| 信号研究 | **一等公民**：跨层特征持续探索，走「研究 → 检验 → 准入 → 监控 → 退役」治理闭环 |
| 数据用途 | 宏观 / 行业 / 个股 / 事件数据 → 规则命中 + 风控通过 + 附证据与失效条件 → 生成推荐 |
| 人的角色 | 决策者：系统给出方案与依据，人确认 / 修改 / 否决，**系统永不自动下单** |
| 复盘 | **决策质量 vs 结果质量分离 + 预期分布 vs 实际结果比对 + 规则级迭代** |

**核心抽象**：不依赖「预测明天涨还是跌」的点预测，同样可以给出决策建议。有效的辅助决策建立在三根支柱上——

1. **状态识别**（现在处于什么环境 / 结构，而非未来价格）；
2. **条件化统计**（历史上类似条件下，收益分布是什么尺度、赔率如何）；
3. **规则与风险约束**（满足什么条件才动手、动多少、什么时候必须走）。

三者组合出的「**条件 → 时机 → 仓位 → 退出 → 验证**」链条，是系统给出建议的完整链路。

### 0.2 运行模式与边界

**四主线闭环**：数据与研判层（行情/财务/资金/事件 → 状态与候选池）→ 决策与风控层（状态 → 条件分布 → 推荐 → 仓位 → 止损止盈 → 硬闸门）→ 执行层（预警 → 人工复核 → 券商端下单 → 成交回填）→ 复盘与迭代层（绩效 / 归因 / 规则优化 → 回到决策层）。

**半自动原则**：系统负责数据采集、指标计算、信号扫描、推荐生成、预警推送；**买卖的最终确认与下单由人工完成**。

**边界（非目标）**：

- 不承诺任何收益率，不以收益率为验收条件；
- 不做全自动无人值守交易；
- 不追求精准预测短期涨跌——推荐建立在概率优势与条件分布上，而非对短期涨跌的点预测，两者并不矛盾；
- **不限制个股推荐本身**：系统完全可以提供个股推荐（含标的与方向），唯一硬约束是必须提供依据。

### 0.3 信号研究的开放性原则

前期方向预测实验的覆盖范围（`predictor_scan.py:1-17` 自述「已经测过的」）：

| 已测实验 | 特征空间 | 目标 |
|---|---|---|
| 20 特征 walk-forward logistic（AUC 0.44–0.54） | 单一个股的价格 / 资金流衍生特征 | 次日方向二分类 |
| OFI 分钟级（AUC≈0.5） | 单一个股分钟订单流不平衡 | 短周期方向 |
| 全球基准同期 / 领先 / 滞后相关（r<0.2） | 指数间线性相关 | 方向传导 |
| 12 特征次日收益 Ridge | 单一个股 12 特征 | 次日收益回归 |

这四项全部落在「**单一个股 × 价格 / 量能衍生特征 × 绝对方向 × 日线 / 分钟**」这一格。系统现有数据已覆盖宏观、市场状态、行业、个股三层，以及事件、资金、画像标签、逐笔行为、多空力量回合等非价格维度，**跨层特征空间尚未被系统检验**。

因此：

- **信号研究是持续开放的一等公民**，阴性结果只关闭该假设，不关闭探索方向；
- 后续可探索方向包括：区制切换模型（只在特定市场状态下有效）、外部事件（财报 / 政策 / 解禁 / 回购）、微观 tick flow 不平衡、跨品种相对价值、波动率与尾部风险预测（这些方向 `predictor_scan.py:655-675` 自身亦有列出）；
- 所有候选信号走统一的检验、准入、监控、退役流程（FR-2.12 / 2.13 / 6.10），不因任何一次实验结论而冻结。

### 0.4 个股推荐与依据规格

系统**完全可以提供个股推荐（含标的与方向）**，决策卡明确给出标的、方向、仓位与价位。**唯一硬约束：一定要提供推荐的依据。**

**推荐依据最小集（每条个股推荐必须同时满足，缺一不可）**

| # | 依据项 | 内容 |
|---|---|---|
| 1 | 规则依据 | 命中的规则 ID + 版本 + `params_hash`；if-then 条件逐条列出当前值、阈值、是否命中 |
| 2 | 状态依据 | 宏观 / 行业 / 个股三层状态与历史分位，以及该状态已持续多久 |
| 3 | 统计依据 | 条件化历史分布的样本量、持有期 N、胜率、盈亏比、收益分位、置信区间，并列无条件基准分布 |
| 4 | 数据依据 | 每个输入的数据源、as-of 时点、新鲜度与覆盖度；断供时不得输出推荐 |
| 5 | 反证与边界 | 反面证据、已知失效场景、明确的失效条件（何时该作废） |
| 6 | 风控依据 | 六项闸门校验结果与仓位计算过程；未通过者不得进入推荐清单 |
| 7 | 可复现依据 | `card_id` + 试验登记簿编号，6 个月后可完整重建 |

> 「可以提供推荐」与「必须给依据」是一体两面：**依据不是推荐的附注，而是推荐成立的资格**。系统不得输出任何无法展开到上述 7 项的标的。

### 0.5 建设目标与需求映射

| 编号 | 建设目标 | 承接方式 | 主要需求 | 验收（§6） |
|---|---|---|---|---|
| **G1** | 从选股到复盘的全流程标准化、可复制 | 「可复制」落实为**规则注册 + 决策卡 8 组字段 + as-of 快照 + 试验登记簿**：任一决策在 6 个月后可按 `card_id` 完整重建，含数据版本、规则版本、参数、试验次数 | FR-2.1 / 2.7 / 2.14、FR-6.12、非功能「研究可复现」 | 决策卡完整率、证据可追溯率 100% |
| **G2** | 跨三大市场的一致性管理与差异化适配 | **一套决策流程 / 口径 / 风控语义 + 一张差异化参数表**（交易单位、日历、时区、货币、税费、成本模型、数据覆盖度），禁止三套并行逻辑；账本统一未复权口径，QFQ 仅供状态计算 | §4 跨市场差异化、FR-3.11、FR-1.7 | 同一规则跨市场结果的口径一致性校验 |
| **G3** | **以概率优势和严格风控实现长期稳健**，而非追求单次暴利 | 概率优势 ≠ 预测涨跌，而是 FR-2.6 条件化历史分布给出的胜率 / 盈亏比 / 期望值**尺度**，叠加 FR-2.13 准入闸门（样本外、多重检验校正、反向安慰剂）与 FR-3.7 硬闸门。系统优化**大数下的期望值**，不是单次输赢；严格风控由三层风险预算与否决权落实 | FR-2.6 / 2.10 / 2.12 / 2.13、FR-3.6 / 3.7 / 3.9 / 3.12 | 扣成本后期望值 >0 才准入；**不设收益率验收** |
| **G4** | 用系统降低情绪干扰，用人工保留最终决策权 | 决策**事前**生成而非临场判断，条件 / 失效 / 退出全部写死在卡里；风控有否决权；系统**输出带依据的个股推荐**，人工确认 / 修改 / 否决并留痕；**永不自动下单** | FR-2.7 / 2.8 / 2.9、FR-3.12、FR-6.5 / 6.11 | 计划外交易占比、强制放行与参数变更留痕率 100% |
| **G5** | 通过数据化复盘持续优化策略 | 闭环驱动力 = **当时预期分布 vs 实际结果的系统性偏差**，不是「赚没赚」；三层归因 + 反事实 + champion–challenger + 衰减监控与退役 | §3.6 全部，重点 FR-6.5 / 6.6 / 6.9 / 6.10 | 实际收益落回预期分布的分位可计算；规则状态迁移全留痕 |

**关于 G3 的口径说明**：「概率优势」依靠的是**条件分布**——在特定状态 / 条件组合下用历史样本估计收益分布与赔率，只在期望值显著为正且风控允许时出手；「不追求精准预测短期涨跌」否定的是**点预测**。两者口径不同，可以并存。

**五条目标之间的约束关系**：G3 回答「为什么出手」，G4 回答「由谁出手」，G2 保证「在哪出手都一致」，G1 保证「过程可复制」，G5 保证「下次更准」。缺任何一条系统都会退化——**缺 G3 只剩记录与拦截、无法形成决策建议，缺 G4 变成黑箱自动交易，缺 G5 变成一套一次性规则**。

## 1. 业界调研：交易与投研系统是怎么做的

> 本节为公开方法论与产品功能调研，用于推导需求依据。文中所有收益 / 胜率数字均为机构历史回测口径，样本区间、基准、成本假设各不相同，**不可横向比较、不代表本系统可达效果、不构成投资建议**。

### 1.1 系统分层（业界共识）

五层 / 六层划分在多个来源高度一致：

| 层 | 职责 | 本项目对应 |
|---|---|---|
| 1 数据层 | 多源接入、清洗、复权、**Point-in-Time 时点隔离**、幸存者偏差处理、流动性过滤 | 已具备（73 表、PIT `regime.macro_series`、QFQ 统一视图） |
| 2 信号 / 研究层（Alpha） | 特征构造、去极值、截面标准化、行业 / 市值中性化、IC / IR 检验、样本外验证 | **部分具备（脚本 stdout），缺研究治理与落库** |
| 3 组合构建层 | 信号 → 目标权重，风险预算、行业 / 风格 / 换手 / 流动性约束 | **缺** |
| 4 执行层 | OMS、拆单、成交回报、滑点 / 冲击、整手约束 | 半自动模式下简化为「人工下单 + 成交回填」 |
| 5 风控层 | **事前预检 / 事中监控 / 事后归因**，独立于策略层、优先级最高 | **缺** |
| 6 监控运维层 | 全链路可观测、策略健康度、告警、模型衰减监控 | 部分具备（`monitor_collector` 用于采集健康，非策略健康） |

三个被反复强调的架构决策：

- **回测与实盘同源**：回测 = 同一系统的「历史回放模式」，只替换事件源，策略 / 风控 / 执行代码不变；
- **事件驱动 + 模块解耦**：策略只做「输入行情 → 输出信号」的纯逻辑，不感知数据来源与执行方式；
- **风控物理独立 + 信号仲裁**：顶层风控必须能覆盖底层策略的买入信号，多策略冲突由仲裁中枢处理。

### 1.2 信号研究的标准闭环与过拟合防护

业界研究流程几乎同构：

```
假设（先有经济逻辑）→ PIT 数据 → 特征构造 → 样本内 IC/IR → 分层回测
    → 样本外 / Walk-forward → 成本与容量检验 → 废弃 / 精修 / 晋升
```

关键的**多重检验防护**（专业与业余的分水岭）：

| 手段 | 作用 |
|---|---|
| 诚实统计试验次数（含被丢弃的变体） | 修正分母，选择偏差的来源 |
| Bonferroni / FDR(BHY) 校正、t 值门槛提高到约 3（Harvey & Liu） | 按试验数抬高显著性门槛 |
| Deflated Sharpe Ratio | 按试验数与收益分布偏度 / 峰度向下修正 Sharpe |
| PBO / CSCV（回测过拟合概率） | PBO>0.40 视为红旗 |
| Lockbox（真正未触碰的最后留出集） | 只允许看一次；反复回看即退化为样本内 |
| Purged K-Fold / CPCV + Embargo | 处理时序重叠与标签泄漏 |
| 参数 ±20% 敏感性（Sharpe 退化 >30% 标记脆弱） | 识别只在单一参数下成立的噪声 |
| 跨市场 / 跨区制 / 跨参数稳健性 | 真信号应在多处出现 |
| **反向安慰剂策略** | 检验收益是来自信号信息量，还是单纯「减少在场时间」 |

因子工程口径：MAD 去极值 → Z-Score 标准化 → **行业 + 市值中性化**（不做的话「高 ROE 因子」可能只是在偷偷买某个行业）→ RankIC / ICIR（机构硬线常见年化 ICIR>1）→ 5/10 分位分层单调性 → 多空与**多头端单独**测试 → 共线性诊断 → 大类内等权、大类间等权（或 ICIR 加权）合成。Barra CNE5/CNE6 的十大风格因子承担风险归因、因子中性化、组合优化三项职能。

### 1.3 跨层决策：宏观择时 → 行业轮动 → 微观时机

这是与本项目**数据布局最契合**的一条业界主线。

**宏观择时**（决定总仓位开关）：主流是「因子打分法」（逻辑透明、对样本依赖小），如五维 12 指标框架按基本面 / 资金面 / 国际面 / 估值面 / 技术面加权，每指标 ±1 票，输出档位仓位。三条硬纪律：① 以**真实发布日期**索引，信号整体滞后一期；② 阈值只用训练期估计、固定应用到检验期；③ 配**反向安慰剂**。另有「三支柱」（方向 / 空间 / 节奏）与「状态分格」（两个滞后宏观变量交叉成四格，逐格检验因子表现）做法。

**行业轮动**（决定方向）：核心是**先分域、再在各域内分别检验因子**。中金 3.0 用「轮动速度 × 集中度」三象限，慢轮动 / 高集中象限用成长与质量因子并叠加拥挤度筛选，快轮动象限因信号衰减快而改用「负面筛选 + 量价排序」的精简规则；西南证券发现因子存在**拥挤度门槛效应**（RDSI 在拥挤度突破临界后失效，IRT 转为负向溢价），开源证券按行业分别识别指标适用性（21 指标周频生成空 / 半 / 满仓）。一个极具警示意义的实证：中金 2.0 模型因用全样本扩展均值划分快慢，导致 2019 年起连续 8 年全判「快轮动」，2026 年市场进入主线集中状态后阶段性失效——**这直接说明模型必须有生命周期管理与分域边界更新机制**。

**微观时机**（决定具体买卖点）：趋势过滤（均线斜率比交叉更重要）、量能验证（放量突破 / 缩量回调）、背离、均线偏离度、拥挤度与情绪结构日频清单、事件日历。三层自上而下叠加：宏观定仓位总开关 → 行业 / 风格定方向 → 微观结构定点。

### 1.4 DSS 与机构平台标本

经典 DSS 是「数据库 + 模型库 + 方法库 / 知识库 + 人机交互」四部分，**由模型驱动**（只有报表没有模型库属于 MIS/BI）。金融 DSS 的五项核心任务：组合优化、风险度量、情景与压力测试、再平衡、筛选；价值主张是「**一致性**」——每次用同一套规则，减少追涨与死扛，并留下决策台账，而不是「比人更聪明」。

| 平台 | 与本需求相关的功能 |
|---|---|
| BlackRock Aladdin | PMS（模型组合 / 基准 / 再平衡 / 实时持仓风险 / 归因）+ OMS + **交易前合规规则引擎**（持仓比例、行业集中度、禁投拦截）+ Aladdin Risk（多因子敞口、蒙特卡洛、情景压力、预测与归因） |
| MSCI Barra PortfolioManager | Brinson / 因子 / 混合三种归因、What-if 情景、多模型多日期多组合并排比较、Optimizer（约束下求解）、Formula Builder 自定义 alpha |
| 国内量化投研平台（多家交集） | 多源数据中心 → 因子研究实验室（预置因子、自定义、IC 分析、因子库沉淀）→ 事件驱动回测（滑点 / 冲击 / 分仓）→ 组合优化 → 业绩归因（分离 Alpha/Beta）→ 实盘 → 全景风控（盘前合规 / 盘中监测 / 盘后归因） |

一个值得借鉴的学术变体：**状态切换型 DSS** = 数据与特征 → 市场状态估计（聚类 + 分类输出状态概率）→ 用户风险画像层（产出离散风险等级）→ 按风险等级求解稳健优化。这与本项目「三层状态 → 风险预算 → 仓位」的设计几乎同构。

### 1.5 对本项目的 8 条设计启示

#### 3.2.3 决策卡字段规格（FR-2.7 的验收基线）

一张决策卡必须同时具备以下 8 组字段，缺任一组视为「未达到辅助决策」：

```
① 标识       card_id / 生成时点 / 标的 / 方向 / 规则ID+版本 / 数据 as-of 时点
② 状态       宏观区制 / 行业状态 / 个股状态（各带历史分位与持续天数，尺度而非分数）
③ 触发       if-then 条件清单（逐条：条件、当前值、阈值、是否命中）
④ 赔率       条件分布：N日、样本量、胜率、盈亏比、p10/p25/p50/p75/p90、
             MFE/MAE、置信区间；并列无条件基准分布；扣成本后期望值
⑤ 时机       入场价格带 / 有效时间窗 / 确认条件 / 失效条件 / 分批节奏
⑥ 仓位       建议股数与金额 + 计算过程（R、止损距离、各项裁剪、成本预估）
⑦ 退出       初始止损 / 移动止损 / 止盈 / 时间止损 / 事件止损 / 状态切换退出
⑧ 校验与反证 风控六项校验结果（通过/拦截+理由）、数据新鲜度、覆盖度、
             反面证据、已知失效场景、人工确认/修改/否决留痕
```

**输出形态约定**：决策卡**明确给出标的、方向、仓位与价位，属于个股推荐**，并写出「在什么条件下成立、依据是什么、什么条件下作废」。它不是自动买入指令——半自动模式下最终由人确认、系统不自动下单。每条推荐必须满足 §0.4「推荐依据最小集」7 项，缺任一项不得进入候选清单；被 FR-3.7 拦截的提案同样不得出现在推荐清单中。

#### 3.2.4 FR-2.6 的计算口径（防止变成又一次自欺）

- 条件检索必须 **as-of**：只用 t 日决策时点真实可得的信息，宏观走 `regime.macro_series` 的 `revision` 与真实发布日期，财务走公告日而非报告期；
- 标签用**未复权成交 / 总回报口径**，不得用 QFQ 前复权价格序列估算收益——`hk_daily_quote` / `a_daily_quote` / `v_daily_quote` 价格列统一 QFQ 且锚定最新交易日，每次除息后需重跑回填重锚历史，会被事后重写，用于账本和收益估计会账实不符；
- 必须报告**样本量**与置信区间，样本不足时明确降级为「证据不足」，不得输出结论；
- 必须与**无条件基准分布**对比，并配**反向安慰剂**，以区分「信号有信息量」与「只是减少了在场时间」；
- 阈值的估计只允许用训练期，固定应用到检验期；Lockbox 只允许打开一次；
- 所有检验记录进试验登记簿（FR-6.12），用于多重检验校正。

#### 3.3.1 基础需求

| 编号 | 需求 | 深化要求 |
|---|---|---|
| FR-3.1 | 硬性止损：买入前设定止损价，触发即强制预警 | 止损价必须**由客观锚计算**（ATR 倍数 / 支撑位 / 结构位），不能随手填；写入决策卡后方可确认；触发后按退出规则集执行并留痕 |
| FR-3.2 | 止盈策略：移动止盈 / 目标估值止盈 | 扩展为 FR-2.9 五类退出规则，全部事前在决策卡中写定 |
| FR-3.3 | 单笔最大亏损限制（如不超过总资金 1%） | 定义为 `R = 账户权益 × risk_pct`，是仓位计算的**分子**，且需与波动率缩放、期望值门槛联动 |
| FR-3.4 | 账户最大回撤控制：触及阈值强制降仓 / 暂停交易 | 分级响应（预警 → 限制开新仓 → 强制降仓 → 全面暂停），并定义恢复条件，避免永久锁死 |
| FR-3.5 | 跨市场汇率风险与总敞口监控 | 统一计价货币、汇率日频、按市场 / 币种拆分敞口、T+2 交收与资金可用性 |

#### 3.3.2 核心需求

| 编号 | 需求 | 说明 | 优先级 |
|---|---|---|---|
| **FR-3.6** | **三层风险预算** | 账户级（最大回撤、日 / 周损失上限、现金下限、总仓位上限由宏观区制决定）→ 组合级（单票上限、单一行业上限、相关性簇上限、风格暴露、流动性上限）→ 单笔级（R、止损距离、期望值门槛）。三层参数全部配置化、版本化 | **P0** |

#### 3.3.3 FR-3.9 仓位计算链（验收基线）

```
R            = 账户权益 × risk_pct                       # 单笔可承受亏损
d            = |entry - stop| / entry                    # 止损距离（客观锚）
raw_qty      = R / (entry × d)                          # 风险预算法原始仓位
期望值门槛    E = p·avg_win − (1−p)·avg_loss − 成本 > 0  # 来自 FR-2.6，否则直接拦截
逐项裁剪      min(单票上限, 行业余量, 总仓位余量, 流动性上限(ADV占比),
                  波动率缩放系数, 凯利上限)
整手化        按市场每手股数向下取整（港股按标的、A股100股、美股1股）
输出          建议股数 + 金额 + 每一步的中间值与被哪项裁剪命中
```

**生命线原则**：

1. **风控优先级高于信号**——赔率再好，越过任何一条红线即拦截；
2. **止损先于入场**——没有止损价的决策卡不允许生成（对应 §6 验收「入场均先有止损价 ≥95%」）；
3. **成本是命题的一部分**——扣成本后期望值 ≤0 的提案不进入候选清单；
4. 所有阈值参数化、版本化，调整需走变更审批（FR-6.9）。

### 3.6 复盘与迭代优化（核心）

**目标**：复盘不是统计「赚没赚钱」，而是回答三个问题——**这次决策当时对不对？系统的预期准不准？下一条规则该改什么？**

#### 3.6.1 基础需求

| 编号 | 需求 | 深化要求 |
|---|---|---|
| FR-6.1 | 绩效统计：胜率、盈亏比、最大连亏、夏普、最大回撤 | 增加 Sortino / Calmar / 波动率 / 换手率 / 实施差额 / 与基准的同期对照；所有指标按**规则版本**分组，而非只看账户总体 |
| FR-6.2 | 归因分析：区分「系统收益」与「运气 / 执行偏差」 | 拆成可计算的三层归因（FR-6.7）+ 反事实执行偏差（FR-6.8），不允许用一句「归因」带过 |
| FR-6.3 | 规则版本管理与 A/B 对比验证 | 升级为 champion-challenger + Lockbox + 参数冻结 + 准入 / 退役生命周期（FR-6.9 / 6.10） |
| FR-6.4 | 生成周期性复盘报告（周 / 月 / 季） | 报告须包含：决策质量分、模型校准偏差、规则级贡献排行、失效预警、待退役清单、本期试验登记摘要 |

#### 3.6.2 核心需求

| 编号 | 需求 | 说明 | 优先级 |
|---|---|---|---|
| **FR-6.5** | **决策质量 vs 结果质量分离** | 每笔交易打两组分：决策质量（规则是否命中、是否事前有止损与失效条件、证据是否充分、是否越过闸门、是否按卡执行）与结果质量（盈亏）。**「赚钱但违规」必须被标为坏决策，「亏钱但合规」是好决策**——这是打破结果偏差的关键 | **P0** |
| **FR-6.6** | **预期分布 vs 实际结果比对** | 把实际收益落回决策卡当时给出的条件分布，看落在哪个分位；系统性右偏 / 左偏 = 模型校准失效；按规则版本聚合，驱动再校准或退役 | **P0** |
| **FR-6.7** | **三层归因** | ① Brinson 配置 / 选择 / 交互（按 HSICS 或申万）；② 因子 / 风格暴露归因，分离 Alpha 与 Beta；③ **规则级归因**（每条规则的期望值、胜率、盈亏比、贡献、IC 衰减、样本外跟踪） | **P0** |
| **FR-6.8** | **反事实分析** | 同期对比「严格按卡执行 / 实际执行 / 不交易 / 不同仓位 / 不同退出点」的结果差异，量化执行偏差成本与择时偏差成本 | **P0** |
| **FR-6.9** | **Champion–Challenger 与变更治理** | 新规则先 paper 观察再小仓位 challenger，与 champion 并行对照；参数冻结、变更审批、效果对比、一键回退；变更理由与试验结果必须留痕（对应 §6 验收「迭代有据可查」） | **P0** |
| **FR-6.10** | **模型衰减监控与退役** | 监控 IC/ICIR 走弱、分层单调性破坏、分布校准漂移、样本外退化、覆盖度下降、市场结构切换（**中金 2.0 于 2026 阶段性失效即分域边界未更新所致**）；触发观察 / 停用 / 退役 | **P0** |
| **FR-6.11** | **行为偏差诊断** | 处置效应（盈利 / 亏损卖出比例）、换手率、注意力驱动买入（是否来自当日热门）、计划外交易占比、否决风控记录、复盘完整率 | P1 |
| **FR-6.12** | **试验登记簿与研究复现** | 每个假设、数据版本、特征构造、参数、**试验次数（含废弃变体）**、样本外结果全部登记；试验次数是多重检验校正的分母，也是「研究可复现」的前提 | **P0** |
| FR-6.13 | 数据质量复盘 | 断供、覆盖塌陷、口径变更、复权重锚对历史结论的影响回溯 | P1 |
| FR-6.14 | 策略健康度看板 | 信号覆盖率、命中率、误报 / 漏报、各规则状态、待退役清单、模型年龄 | P1 |

#### 3.6.3 迭代闭环

```
决策卡(as-of 快照 + 预期分布)
    ↓ 人工确认
成交事实（含费用与滑点）
    ↓
FR-6.5 决策质量评分  ┐
FR-6.6 分布校准偏差  ├→ FR-6.7 三层归因 → FR-6.8 反事实
FR-6.12 试验登记簿   ┘
    ↓
FR-6.10 衰减监控 → FR-2.13 准入/退役 → FR-6.9 Champion–Challenger
    ↓
规则新版本（params_hash + 变更审批）→ 回到决策卡
```

**关键**：闭环的驱动力是「**当时预期 vs 实际结果的系统性偏差**」，不是「这次赚了还是亏了」。这使系统能从自己的交易结果里学习，也让 §3.2 的信号研究永远有新的实证输入。

## 6. 关键验收指标

系统是否「达标」以**过程与决策质量指标**为主，不以收益率、胜率高低或回测表现作为验收条件。

| 类别 | 指标 |
|---|---|
| **基础过程指标** | ① 每笔交易入场均先有止损价，执行率 ≥95%；② 交易计划与日志记录完整率 ≥95%；③ 预警漏报 / 误报率在可接受范围且可追溯；④ 账户最大回撤始终处于预设阈值内；⑤ 月度复盘报告按时产出；⑥ 规则迭代有据可查（版本、理由、效果对比） |
| **决策质量（3.2）** | ① 每笔交易可关联到一张含 8 组字段的完整决策卡；② 每张卡的规则 ID / 版本、条件阈值、数据源 as-of 100% 可追溯；③ 条件分布必须报告样本量与置信区间，样本不足时降级率 100% 记录；④ 数据断供期间新决策卡生成数 = 0；⑤ 推荐清单中每一条的依据链 7 项完整率 100% / 可展开率 100%；排序键可解释；不存在只给综合分而无依据的条目 |
| **风控有效性（3.3）** | ① 六类违规样例 100% 被服务端拦截并给出准确条款；② 无止损价的决策卡生成数 = 0；③ 被拦截 / 强制放行 / 参数变更 100% 留痕；④ 决策卡与回测使用同一套成本模型，实施差额定期回校 |
| **研究与迭代（3.6）** | ① 每个准入信号有经济逻辑说明、试验次数、多重检验校正、样本外 / Lockbox 结果、参数敏感性与反向安慰剂；② 每笔交易同时有决策质量分与结果质量分；③ 实际收益落回预期分布的分位可计算；④ 规则状态迁移（候选 → 观察 → 准入 → 停用 → 退役）全留痕；⑤ 衰减告警有响应记录 |

## 附录 B · 业界调研参考（方法论，非收益依据）

- 系统分层：工业级量化五层架构（数据 PIT / 信号 / 组合 / 执行 / 风控归因）、六层含监控运维；Aladdin（PMS + OMS + 交易前合规 + Risk）、Barra PortfolioManager（Brinson / 因子 / 混合归因、What-if、Optimizer、Formula Builder）；国内量化投研平台功能栈（数据中心 → 因子实验室 → 事件驱动回测 → 组合优化 → 归因 → 实盘 → 全景风控）。
